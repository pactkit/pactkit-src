# BUG-022: load_config shallow merge loses nested dict defaults

| Field     | Value |
|-----------|-------|
| Status    | Closed |
| Author    | System Architect |
| Release   | 1.3.2 |

## Context

`load_config()` in `config.py` performs a shallow merge of user YAML over defaults:

```python
merged = dict(default)
for key, value in user_data.items():
    if key in merged:
        merged[key] = value
```

For nested dict sections (`venv`, `ci`, `hooks`, `issue_tracker`), the entire user dict replaces the entire default dict. This means default sub-keys are silently lost when the user specifies only a subset.

### Example

Default config:
```yaml
venv:
  auto_detect: true
```

User config:
```yaml
venv:
  path: custom_venv
```

After merge: `{'path': 'custom_venv'}` — `auto_detect` is gone.

### Current Impact

Currently masked because downstream code uses `venv_config.get('auto_detect', True)` with an explicit default fallback. But this creates a fragile pattern where every consumer must independently know the correct default, and adding new nested keys will silently break if any consumer forgets the fallback.

## Target Call Chain

```
config.py:load_config(path)
  → default = get_default_config()          # has venv: {auto_detect: True}
  → user_data = yaml.safe_load(raw)         # has venv: {path: "custom_venv"}
  → merged = dict(default)
  → merged['venv'] = user_data['venv']      # BUG: entire dict replaced
  → return merged                           # venv.auto_detect lost
```

## Requirements

### R1: Deep Merge for Nested Dict Sections
- For config keys whose default value is a `dict`, `load_config` MUST perform a deep merge: default sub-keys are preserved, user sub-keys override matching defaults.
- The affected keys are: `venv`, `ci`, `hooks`, `issue_tracker`.

### R2: Non-Dict Keys Unchanged
- For top-level keys with non-dict values (strings, lists, booleans), the current shallow override behavior MUST be preserved.
- List-type keys (`agents`, `commands`, `skills`, `rules`) MUST continue to be fully replaced by user values.

### R3: Explicit User Values Win
- IF the user specifies `venv: {auto_detect: false, path: custom}`, both keys MUST appear in the merged result.
- User values MUST override defaults, not the other way around.

### R4: Backward Compatibility
- Existing `pactkit.yaml` files that already specify complete nested sections MUST produce identical merge results.
- The merge change MUST NOT affect `auto_merge_config_file` behavior (which operates on the raw YAML, not `load_config`).

## Acceptance Criteria

### AC1: Partial venv Section Preserves Defaults
- **Given** default config has `venv: {auto_detect: true}`
- **And** user YAML has `venv: {path: ".venv"}`
- **When** `load_config()` is called
- **Then** merged config has `venv: {auto_detect: true, path: ".venv"}`

### AC2: User Override Wins
- **Given** default config has `venv: {auto_detect: true}`
- **And** user YAML has `venv: {auto_detect: false}`
- **When** `load_config()` is called
- **Then** merged config has `venv: {auto_detect: false}`

### AC3: Partial hooks Section Preserves Defaults
- **Given** default config has `hooks: {pre_commit_lint: false, post_test_coverage: false, pre_push_check: false}`
- **And** user YAML has `hooks: {pre_commit_lint: true}`
- **When** `load_config()` is called
- **Then** merged config has all three hook keys, with `pre_commit_lint: true` and the rest `false`

### AC4: Full Section Override Unchanged
- **Given** user YAML has `ci: {provider: github}`
- **When** `load_config()` is called
- **Then** merged config has `ci: {provider: github}` (identical to current behavior)

### AC5: Non-Dict Keys Unaffected
- **Given** user YAML has `stack: node` and `lint_blocking: true`
- **When** `load_config()` is called
- **Then** `stack` is `node` and `lint_blocking` is `true` (shallow override preserved)

### AC6: List Keys Fully Replaced
- **Given** user YAML has `agents: [senior-developer]`
- **When** `load_config()` is called
- **Then** `agents` is `[senior-developer]` (not merged with default agent list)
