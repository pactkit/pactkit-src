## Background

2026-09-02 harness-backend 批量提交事故:第 5 个 commit 的 gate 运行被拦,报
"[FAIL] no tests collected — treated as RED"——实际 331 个测试跑了、有 flaky 失败。根因是两个缺陷叠加:

1. **解析盲区(持续存在)**:gate 以 `pytest -rs -q` 跑套件,从终端 summary 行
   ("N passed, M failed in Xs")解析计数;repo pyproject 的 `addopts = "-q"` 叠加成
   `-qq`(verbosity -2),**pytest 9.x 在 -qq 下不打印最终 summary 行** →
   `parse_pytest_summary` 永远全 0。绿灯时隐形(rc=0 不检查计数),真红时才引爆。
2. **触发(瞬态)**:该次运行真实 flaky 红(rc≠0;lastfailed 缓存法证确认其完成了
   sessionfinish 并写入了失败记录,排除了"子进程被杀"假说)。

rc≠0 + 计数全 0 命中 `collected == 0` 分支,文案断言 "no tests collected"——与事实
(331 ran, some failed)脱节,把排查引向"子进程被杀 / OS kill"方向。另实测:-qq 下终端
仍打印 `FAILED ...` short summary,但该分支的 tail 过滤器只抓 `ERROR` 前缀,失败信息
也被丢弃。

规划期探针验证(pytest 9.1.1 与 9.0.2 双确认):

- `-qq --junitxml=X` → `<testsuite>` 元素携带精确计数(errors/failures/skipped/tests),
  与终端 verbosity 无关
- `-p no:junitxml --junitxml=X` → exit 4 "unrecognized arguments"(病态 repo 配置会让
  gate 自锁,必须识别并降级)
- `-o junit_family=xunit2` 可钉住 XML 格式

## Requirements

### R1: 计数可得性——junitxml 权威通道 (MUST)

`run_pytest` 的 Python 栈调用 MUST 追加 `--junitxml=<临时文件>`(tempfile.mkstemp,
系统临时目录)与 `-o junit_family=xunit2`。套件执行 MUST 完全保留 repo 的 addopts
(包括 `--asyncio-mode=auto` 等必需运行参数;不采用 `-o addopts=` 清空方案——清空会
改变套件语义,可能把绿套件跑红)。计数 MUST 以 XML `<testsuite>` 属性为准
(passed = tests − failures − errors − skipped);终端 `_SUMMARY_RE` 解析降级为 fallback。
临时文件 MUST 在 finally 中删除;junitxml 内容 MUST NOT 持久化或写入任何日志/审计记录
(测试输出可能包含敏感串)。非 Python 栈(node/go/java)不适用本条,维持现状。

### R2: junitxml 不可用时的优雅降级 (MUST)

当 pytest 以 exit 4 结束且输出含 "unrecognized arguments" 与 "--junitxml" 时,gate
MUST 去掉 junitxml 旗标重试一次(usage error 瞬时返回,无二次全套件时间成本)。
实施探针修正:ini 级 `addopts = "-p no:junitxml"` 静默接受旗标但**不写 XML**——主降级
路径是文件缺失 → `parse_junit_counts` 返回 None → 终端 fallback;exit-4 拒收仅在
CLI 级 `-p` 出现(gate 自身 argv 不可达),作为防御分支保留。重试结果 MUST 走终端
fallback 解析。全程 MUST NOT 因 gate 自身旗标问题把绿套件误拦(自锁保护,R3 语义:
gate 自身不可用时 WARN + 放行)。

### R3: 失败文案真实化 (MUST)

rc≠0 时的文案 MUST 按退出码区分,不再一律断言 "no tests collected":

- exit 5 → 明示 "no tests ran"(保持 RED-阻断语义:代码变更需要套件验证)
- exit 4 → usage/collection error + 输出 tail
- 其他 rc≠0 且计数可得 → "tests RED — N failed, M errors"(现状保持)
- 其他 rc≠0 且计数不可解析 → MUST 报 "pytest exited {rc} but counts unparseable",
  附 repo addopts 可能吞掉 summary 行的提示,并给出手动复跑命令建议

零计数分支的 tail 过滤器 MUST 从仅 `ERROR` 前缀扩展为 `FAILED|ERROR` 前缀(-qq 下
FAILED short-summary 仍打印,事故现场本可展示)。

### R4: 回归测试 (MUST)

AC1–AC5 各自映射 `docs/test_cases/` 中的可验证用例;fixtures 用 tmp_path 构造带
`addopts` 的最小 repo,不依赖外部队列。

### R5: 文档 (SHOULD)

CHANGELOG 记录本行为变更;README enforcement gates 段落若描述计数行为则同步。

## Acceptance Criteria

### AC1: 事故复现——addopts 叠加 + 真红 (R1, R3)

- **Given** 最小 fixture repo:pyproject `addopts = "-q"`,tests/unit 含 3 个测试(2 过 1 败)
- **When** run_gate 触发(gate 的 `-rs -q` 与 addopts 叠加为 `-qq`)
- **Then** 拦截发生(rc≠0,fail-closed 不变),计数为真实值(1 failed / 2 passed,非全 0),
  文案为 tests RED,输出包含 `FAILED ...` tail 行

### AC2: 绿灯 + addopts 叠加 (R1)

- **Given** 同 AC1 fixture 但套件全绿
- **When** run_gate 触发
- **Then** 放行,计数行显示真实计数(非 "0 passed, 0 failed")

### AC3: junitxml 被禁用的 repo (R2)

- **Given** fixture repo `addopts = "-p no:junitxml"`,套件全绿
- **When** run_gate 触发(实施探针修正:ini 级 `-p` 静默接受旗标但不写 XML,
  主降级路径是"文件缺失 → None → 终端 fallback",不产生 exit 4;exit-4 拒收
  为 CLI 级形态,gate 自身 argv 不可达,作为防御分支保留并以合成触发测试)
- **Then** 放行,不产生自锁;计数来自终端 fallback;防御分支在拒收签名下去旗标重试

### AC4: exit 5——空收集 (R3)

- **Given** fixture repo 测试选择结果为空集(pytest exit 5)
- **When** run_gate 触发
- **Then** 拦截,文案明示 "no tests ran"(exit 5),不使用 "no tests collected" 措辞

### AC5: 双重病态——计数不可解析 (R3)

- **Given** fixture repo `addopts = "-q -p no:junitxml"`(去旗标重试后仍为 -qq,无 summary 行)
  且套件含失败
- **When** run_gate 触发
- **Then** 拦截,文案报 "pytest exited 1 but counts unparseable" + addopts 干扰提示,
  MUST NOT 断言 "no tests collected"

### AC6: 全量回归 (R4)

- **Given** 实现完成
- **When** 运行项目全量测试套件
- **Then** 全绿,含既有 commit-gate 测试(test_commit_gate.py、test_hotfix_20260901_gate_docsonly.py)

### AC7: 文档同步 (R5)

- **Given** 变更落地

- **Then** CHANGELOG 有本条目;README 若描述 gate 计数行为则与实现一致
