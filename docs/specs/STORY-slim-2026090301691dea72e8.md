## Background

2026-09-03 对话记录实证分析（487MB transcripts / ~100 sessions / 70 条用户纠正 / 166 次 PDCA 调用）暴露四个规则层缺口，均有量化证据：

1. **Capability Assessment 遵循率 ~2%**：`/project-plan` 全历史 56 次调用中 Capability Assessment 表格仅产出 1 次（且是旧版 160 行规则时期）。同日 capsule 修复（capability-design 补产出物格式）只解决"触发时做对"；trigger 判断权在模型手里，code 层门禁才能保证"被触发"。
2. **"没读项目域材料"是最高频纠正类别**：pactsearch 三次同类纠正（"你应该去看 semantic rules 啊"/"你根本就没读好"/"先去看看再决定怎么做"）；对照组——semantic_rules wiki 被 Read 200+ 次的 session 全部顺利。`spec_preflight` 的 `## Implementation Inputs` 声明机制已全量存在（表声明 + backtick 自动发现），但 plan 阶段无 MUST 要求把域材料声明进去。
3. **验证 setup 造假**：admin 用户测业务权限问题（权限太大发现不了）、声称测试但数据源未保存、测试跑在未清理的旧进程上。现有 `fresh evidence` 语义只有时间维度，缺 actor 对齐与环境同源维度。
4. **Whack-a-mole 修复**："总是在发现问题改一次，没有一次性解决的方法"——发现单个缺陷后不扫同类位点。

## Requirements

### R1: spec-lint W012 Capability Assessment 门 (MUST)

spec-lint MUST 新增 W012 规则：当 `## Technical Design` 节存在且其文本含框架/依赖信号（`pyproject.toml` / `package.json` / `go.mod` / `pom.xml` / `build.gradle` / `requirements.txt` / `Cargo.toml` / `framework`，大小写不敏感），但缺少 `### Capability Assessment` 子节时，输出 W012 warning。信号未命中或子节存在时 MUST NOT 触发。W012 MUST NOT 影响 `LintResult.passed`（非阻塞）。

### R2: Plan 阶段域材料声明 (MUST)

project-plan playbook Phase 2 MUST 新增步骤：当需求触及领域逻辑（业务规则、数据模型、semantic layer、领域术语）时，Spec MUST 在 `## Implementation Inputs` 表中声明治理性域材料（数据字典、semantic layer、需求文档等）的 path 与 purpose，使 Act Phase 0.7 spec-preflight 确定性加载。纯基础设施/工具链改动 MUST 声明 skip 理由。

### R3: Check 验证语义补强——setup 对齐 + 环境同源 (MUST)

check contract invariants MUST 增加 "verification setup matches the Spec's actor and environment"；completion evidence MUST 增加 "test environment provenance is confirmed (running code == code under test)"。check playbook Phase 3.5 MUST 增加 setup-actor mismatch 反模式（测试以特权路径行使 Spec 场景中的终端用户路径）；Phase 4 MUST 在 E2E 前增加环境溯源前置检查（进程/配置运行的是被测代码）。done contract completion evidence MUST 同步一行（"adequate" 的定义含 actor 与环境维度）。

### R4: Defect-class sweep (MUST)

check contract invariants MUST 增加 "a defect finding sweeps its class — same-pattern sites are checked before a pass verdict"。check playbook Phase 2 MUST 增加 sweep 步骤：对每个发现或修复的缺陷，用 grep/visualize 扫同模式位点并在 verdict 中报告同类位点清单。

### R5: Adapter parity 与契约预算有界 (SHOULD)

所有 playbook/contract 改动经 `_render_prompt` 部署到四个 adapter（claude/opencode/codex/copilot）且语义一致；每个 phase contract capsule 新增行数 SHOULD ≤ 3 行（maintainer overlay 的 bounded prompt budgets）。
