# BUG-021: Generated project CLAUDE.md ignores LANG_PROFILES, hardcodes Unix paths, and contradicts Playbook

| Field     | Value |
|-----------|-------|
| Status    | Closed |
| Author    | System Architect |
| Release   | 1.3.2 |

## Context

`_generate_project_claude_md_if_missing()` was added in BUG-019/020 but was not aligned with the existing `LANG_PROFILES` integration pattern used by `_deploy_ci()` and `_deploy_hooks()`. Three interrelated issues exist in this single function:

1. **Playbook contradiction**: `project-init.md` (Tier 1) says "do NOT overwrite if it already exists", but the function always overwrites (with backup). The function name `_if_missing` is also misleading.
2. **Windows path breakage**: `detect_venv()` correctly detects Windows venvs (`Scripts/python.exe`), but the generated CLAUDE.md hardcodes Unix paths (`source {venv}/bin/activate`, `{venv}/bin/python3`). Detection succeeds on Windows, but output is wrong.
3. **Hardcoded lint/test commands**: Lint is hardcoded to `ruff check src/ tests/` and test runner to `pytest tests/ -v`, ignoring the `stack` config and `LANG_PROFILES`. For Node/Go/Java projects, the CLAUDE.md contains wrong commands. The Playbook template explicitly requires `{lint_command from LANG_PROFILES}` and `{test_runner from LANG_PROFILES}`.

### Root Cause

The function receives the full `config` dict (which contains `stack`) but never reads it and never consults `LANG_PROFILES`. Other deployer functions (`_deploy_ci` at line 537, `_deploy_hooks` at line 629) follow the correct pattern.

## Target Call Chain

```
cli.py:main()
  → deployer.deploy()
    → _deploy_classic(config, target)
      → _generate_project_claude_md_if_missing(config)  # target=None guard exists
        → detect_venv(project_root)       # returns candidate name, no OS layout info
        → hardcoded "source {venv}/bin/activate"   # BUG: Unix-only
        → hardcoded "ruff check src/ tests/"       # BUG: ignores LANG_PROFILES
        → hardcoded "pytest tests/ -v"             # BUG: ignores LANG_PROFILES
        → atomic_write(claude_md_path, ...)        # BUG: always writes, contradicts Playbook
```

## Requirements

### R1: Respect Playbook Overwrite Policy
- IF `.claude/CLAUDE.md` already exists, the function MUST skip generation and return immediately.
- The Playbook (Tier 1) instruction "do NOT overwrite if it already exists" MUST be honored.
- The BUG-020 backup-and-overwrite behavior MUST be removed to align with Tier 1.
- Rename the function or keep the name `_generate_project_claude_md_if_missing` and make behavior match the name.

### R2: Platform-Aware Venv Commands
- `detect_venv()` MUST return both the venv directory name AND the detected layout (`unix` or `windows`).
- IF the layout is `unix`, generate commands using `bin/activate`, `bin/python3`, `bin/pytest`, `bin/pip`.
- IF the layout is `windows`, generate commands using `Scripts/activate`, `Scripts/python.exe`, `Scripts/pytest.exe`, `Scripts/pip.exe`.
- The activate command MUST use `source` on Unix and direct path on Windows.

### R3: Stack-Aware Lint Command
- The function MUST read `config.get('stack', 'auto')` and resolve it via `LANG_PROFILES`.
- The lint command in the generated CLAUDE.md MUST come from `LANG_PROFILES[stack]['lint_command']`.
- IF the stack is `auto`, fall back to `python` profile (consistent with `_deploy_ci`).

### R4: Stack-Aware Test Runner
- The test runner command MUST come from `LANG_PROFILES[stack]['test_runner']`.
- IF venv is detected (Unix layout), prefix the test runner with `{venv_path}/bin/`.
- IF venv is detected (Windows layout), prefix with `{venv_path}/Scripts/`.
- IF no venv, use the bare test runner command from `LANG_PROFILES`.

### R5: Backward Compatibility
- Projects without venv MUST still get a valid CLAUDE.md with correct stack-specific commands.
- The `@./docs/product/context.md` reference MUST be preserved.
- The function MUST still skip when `target is not None` (preview mode) — existing guard at deployer line 134.

## Acceptance Criteria

### AC1: Skip When File Exists
- **Given** `.claude/CLAUDE.md` already exists with user content
- **When** `pactkit init` is run (deployer `_deploy_classic`)
- **Then** `.claude/CLAUDE.md` is NOT modified
- **And** no `.bak` file is created
- **And** no "Backed up" message is printed

### AC2: Generate When Missing
- **Given** `.claude/CLAUDE.md` does NOT exist
- **And** `.venv/bin/python3` exists (Unix venv)
- **When** `pactkit init` is run
- **Then** `.claude/CLAUDE.md` is created with `source .venv/bin/activate` commands

### AC3: Windows Venv Commands
- **Given** `.claude/CLAUDE.md` does NOT exist
- **And** `.venv/Scripts/python.exe` exists (Windows venv)
- **When** `pactkit init` is run
- **Then** `.claude/CLAUDE.md` contains `.venv/Scripts/python.exe` (not `bin/python3`)
- **And** activate command does NOT use `source ... /bin/activate`

### AC4: Node Stack Uses eslint
- **Given** `.claude/CLAUDE.md` does NOT exist
- **And** `pactkit.yaml` has `stack: node`
- **When** `pactkit init` is run
- **Then** `.claude/CLAUDE.md` lint section contains `npx eslint .` (not `ruff`)
- **And** test section contains `npx jest` (not `pytest`)

### AC5: Go Stack Uses golangci-lint
- **Given** `.claude/CLAUDE.md` does NOT exist
- **And** `pactkit.yaml` has `stack: go`
- **When** `pactkit init` is run
- **Then** `.claude/CLAUDE.md` lint section contains `golangci-lint run`
- **And** test section contains `go test ./...`

### AC6: Auto Stack Falls Back to Python
- **Given** `.claude/CLAUDE.md` does NOT exist
- **And** `pactkit.yaml` has `stack: auto` (or no stack key)
- **When** `pactkit init` is run
- **Then** `.claude/CLAUDE.md` contains `ruff check src/ tests/` and `pytest tests/ -v`

### AC7: detect_venv Returns Layout Info
- **Given** a project root with `.venv/bin/python3`
- **When** `detect_venv(project_root)` is called
- **Then** return value includes both the directory name (`.venv`) and layout (`unix`)

### AC8: detect_venv Windows Layout
- **Given** a project root with `venv/Scripts/python.exe`
- **When** `detect_venv(project_root)` is called
- **Then** return value includes both the directory name (`venv`) and layout (`windows`)
