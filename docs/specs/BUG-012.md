# BUG-012: Call graph drowns signal in noise — filter builtin/stdlib calls

- **Type**: Bug
- **Priority**: High
- **Release**: 1.2.0
- **Discovered**: 360-degree audit (third pass), user feedback on graph quality

## Context

The `visualize --mode call` graph (call_graph.mmd) generates 464 lines of noise because `_extract_calls()` captures every `ast.Call` indiscriminately. Calls to builtins (`isinstance`, `len`, `sorted`, `set`, `dict`, `type`, `print`, `any`), method calls on local variables (`lines.append`, `data.get`, `path.exists`), and stdlib functions flood the graph, making it useless for understanding actual project-internal call chains.

A useful call graph should show only project-defined function-to-function relationships (e.g., `_deploy_classic` → `_deploy_agents` → `atomic_write`), filtering out noise that doesn't represent actual architectural dependencies.

## Root Cause

`_extract_calls()` (visualize.py:328-342) walks all `ast.Call` nodes and captures:
- `ast.Name` calls → captures builtins like `isinstance`, `len`, `sorted`, `print`
- `ast.Attribute` calls → captures `lines.append`, `data.get`, `path.exists`

No filtering is applied. The `_resolve_callee` function tries to match callees to `func_registry` but unresolved names are still kept as leaf nodes, creating hundreds of noise nodes.

## Target Call Chain

```
visualize(mode='call') → _build_call_graph() → _extract_calls() → produces noise
```

Fix is in `_extract_calls()` and `_build_call_graph()`.

## Requirements

1. **MUST** filter out Python builtins from call graph nodes (`isinstance`, `len`, `sorted`, `set`, `dict`, `type`, `print`, `any`, `str`, `int`, `float`, `bool`, `list`, `tuple`, `range`, `enumerate`, `zip`, `map`, `filter`, `super`, `hasattr`, `getattr`, `setattr`, `repr`, `min`, `max`, `abs`, `round`, `open`, `ValueError`, `TypeError`, `KeyError`)
2. **MUST** filter out method calls on non-`self` local variables (e.g., `lines.append`, `data.get`, `path.exists`, `content.replace`) — these are method calls on local data, not project-internal function calls
3. **MUST** retain calls to project-defined top-level functions (e.g., `_deploy_agents`, `atomic_write`, `load_config`)
4. **MUST** retain calls to `self.method()` (resolved to `ClassName.method`) for class-based projects
5. **SHOULD** in `_build_call_graph`, only include edges where at least one endpoint is a project-defined function (registered in `func_registry`)
6. **MUST NOT** break existing `--entry` BFS tracing (which follows resolved edges only)

## Acceptance Criteria

### AC1: Builtins filtered from call graph
- **Given** PactKit source with calls to `isinstance`, `len`, `sorted`, etc.
- **When** `visualize --mode call` is run
- **Then** the call_graph.mmd does NOT contain nodes for builtin functions

### AC2: Local method calls filtered
- **Given** code like `lines.append(...)`, `data.get(...)`, `path.exists()`
- **When** `visualize --mode call` is run
- **Then** these do NOT appear as nodes in call_graph.mmd

### AC3: Project-internal calls preserved
- **Given** code calling `_deploy_agents(...)`, `atomic_write(...)`, `load_config(...)`
- **When** `visualize --mode call` is run
- **Then** these appear as edges in call_graph.mmd

### AC4: Entry-point tracing still works
- **Given** `visualize --mode call --entry deploy`
- **When** BFS traversal runs from `deploy` function
- **Then** the transitive call chain shows only project-internal functions

### AC5: Significant noise reduction
- **Given** the current 464-line call_graph.mmd
- **When** BUG-012 fix is applied
- **Then** the call graph has meaningfully fewer nodes (target: < 100 lines for PactKit's 20 project functions)
