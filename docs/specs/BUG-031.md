# BUG-031: CLAUDE.local.md Docstring Contradicts Managed Block Behavior

| Field       | Value                          |
|-------------|--------------------------------|
| ID          | BUG-031                        |
| Title       | CLAUDE.local.md docstring contradicts managed block behavior |
| Priority    | P3                             |
| Status      | Backlog                        |
| Release     | 1.6.7                         |
| Found In    | v1.6.7 code review             |
| Root Cause  | Stale comment after STORY-064  |

## Summary

`_generate_claude_local_md_if_missing()` docstring (deployer.py:742-744) states "This file is user-owned and never modified by PactKit after initial creation", but STORY-064 introduced `_upsert_venv_managed_block()` which explicitly modifies `CLAUDE.local.md` on every deploy. The comment contradicts the actual behavior and may mislead future developers.

## Requirements

### R1: Update function docstring
The docstring of `_generate_claude_local_md_if_missing()` MUST be updated to clarify that PactKit manages a venv block within the file via `_upsert_venv_managed_block()`.

### R2: Update template comment
The inline template comment ("PactKit will never overwrite this file") SHOULD be revised to "PactKit manages a venv block at the top; user content below is preserved."

## Acceptance Criteria

### AC1: Docstring accurately describes behavior
- **Given** the deployer source code
- **When** reading `_generate_claude_local_md_if_missing()` docstring
- **Then** it mentions that the managed venv block is an exception to the "never modified" rule

### AC2: Template comment updated
- **Given** a fresh `pactkit init`
- **When** CLAUDE.local.md is created
- **Then** the template comment explains the managed block convention
