## Background

Full-codebase review (2026-08-26) found two contradictory resolution
orders inside the same module (config.py), verified on the working tree:

- **Read path**: find_pactkit_yaml (config.py:676) resolves the effective
  config via profiles.PACTKIT_YAML_CANDIDATES ordered
  opencode > codex > copilot > classic — comment: "newer environments
  preferred". Every consumer (load_config, deployer, doctor, guards)
  reads the **opencode** copy in a multi-format project.
- **Sync path**: sync_config_copies (config.py:729 region) declares
  classic (.claude) first canonical (CANONICAL_PREFERENCE) — comment:
  "the copy humans actually edit" — and overwrites all other copies with
  .claude's content on every update.

Net effect in a project with both copies: the user edits the file that
is actually loaded (opencode's), then `pactkit update` (cli.py runs sync
before deploy) silently destroys those edits with .claude's stale
content. The two orderings carry directly contradictory rationales; one
is wrong.

Additionally the sync write is non-atomic (config.py:756
`copy_path.write_text(...)`) — a crash mid-write truncates the very file
whose corruption breaks every subsequent command. The atomic
tmp-plus-os.replace pattern already exists in the same module
(_rewrite_yaml, config.py:1105 region) and in utils.atomic_write.

Lateral scan: atomic_write exists (utils.py) and MUST be reused;
find_pactkit_yaml exists and MUST be the single resolution authority.

## Requirements

### R1: One canonical resolution order (MUST)

find_pactkit_yaml and sync_config_copies MUST derive their ordering from
a single shared constant in profiles.py (single source of truth). The
sync source MUST be exactly the copy find_pactkit_yaml resolves as the
effective config — the file being read MUST be the file being
propagated, so user edits to the effective copy can never be destroyed
by sync.

### R2: Atomic sync writes (MUST)

sync_config_copies MUST write each copy via the atomic
tmp-plus-os.replace pattern (reuse utils.atomic_write or the
_rewrite_yaml helper); a crash mid-sync MUST NOT leave a truncated
pactkit.yaml in any copy.

### R3: Divergence warning (SHOULD)

When the non-canonical copies differ from the effective copy before
sync, the sync SHOULD print which copies are being overwritten and by
how many bytes/lines, so silent destruction becomes visible.

## Acceptance Criteria

### AC1: effective copy propagates, not .claude (R1)

- **Given** a project with .opencode/pactkit.yaml and .claude/pactkit.yaml, and the opencode copy modified by the user
- **When** sync_config_copies runs
- **Then** .claude/pactkit.yaml receives the opencode copy's content and the opencode copy is unchanged

### AC2: readers and sync agree (R1)

- **Given** any combination of pactkit.yaml copies on disk
- **When** find_pactkit_yaml resolves the effective copy and sync_config_copies runs
- **Then** the sync source path equals the find_pactkit_yaml result (verified by test on both orderings' fixture matrix)

### AC3: crash-safe sync (R2)

- **Given** a sync interrupted between write and replace (simulated by monkeypatched os.replace raising)
- **When** sync_config_copies runs
- **Then** the pre-existing copy content is intact (no truncated file)

### AC4: divergence is reported (R3)

- **Given** .claude/pactkit.yaml differing from the effective copy
- **When** sync runs
- **Then** stdout names the overwritten copy and its change size

## Target Call Chain

```
cli.py (init/update)
  → config.py: find_pactkit_yaml        [R1 — read authority]
             : sync_config_copies       [R1/R2/R3 — derives from same constant]
             : _rewrite_yaml            [R2 — existing atomic pattern to reuse]
  → profiles.py: PACTKIT_YAML_CANDIDATES (shared order constant)  [R1]
  → utils.py: atomic_write              [R2]
```
