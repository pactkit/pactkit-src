## Problem

`test_story016_claude_md.py::test_has_architecture_in_local` was relaxed to `assert len(content.strip()) > 0` after 3 CI rounds failed on environment-specific content. The current assertion is a placeholder — it verifies the file is non-empty but does not validate the expected content structure.

## Root Cause

In CI, `.claude/CLAUDE.local.md` is created by test-invoked `deploy()` calls with varying content depending on the environment (venv detection, format selection). The original test asserted specific content patterns (`src/pactkit/`, `Architecture`, `Project Local Instructions`, `pactkit:venv:start`) that don't cover all CI scenarios.

## Requirements

### R1: Environment-aware assertion
The test should assert content that is valid for both local dev and CI environments. Options:
- Assert the file matches one of N known valid content patterns (union check)
- Mock the environment so CI produces the same output as local
- Skip the test in CI if the file is generated by side effects (mark with `@pytest.mark.skipif`)

### R2: No regression on local
The fix must not weaken assertions for the local development case where the file contains user-modified content.

## Acceptance Criteria
- [ ] R1: Test passes in CI without `assert non-empty` placeholder
- [ ] R2: Test still validates meaningful content locally
