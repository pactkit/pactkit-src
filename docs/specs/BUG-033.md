# BUG-033: scaffold.py create_spec() 生成的模板不符合 spec-lint 验证规则

| Field | Value |
|-------|-------|
| ID | BUG-033 |
| Status | Done |
| Priority | P1 |
| Release | 1.6.8 |

## Background

`/project-plan` 完成后执行 `/project-act` 时，会在 Phase 0.5 运行 `pactkit spec-lint` 验证 Spec 格式。当前 `scaffold.py::create_spec()` 生成的模板格式与 `spec_linter.py` 的验证规则不匹配，导致所有新生成的 Spec 都无法通过验证。

**错误信息**:
```
[ERROR] E001: Missing metadata table (| Field | Value | header not found)
[ERROR] E004: Requirements section has no '### R{N}:' subsections
```

## Root Cause

`src/pactkit/skills/scaffold.py` 的 `create_spec()` 函数 (line 49-80) 生成的模板格式过时：

| 规则 | spec_linter 期望 | scaffold.py 生成 | 匹配 |
|------|-----------------|-----------------|------|
| E001 | `\| Field \| Value \|` 表格 | `- **Release**: TBD` bullet | No |
| E002 | ID, Status, Priority, Release | 只有 Release | No |
| E004 | `### R1:` 子标题 | 纯 bullet list | No |
| E006 | `### AC1:` 或 `### Scenario N:` | `### Scenario 1:` | Yes |
| E008 | Release 不能是 TBD | 默认 TBD | No |

## Requirements

### R1: Metadata Table Format
The `create_spec()` function MUST generate a metadata table with `| Field | Value |` header containing ID, Status, Priority, Release fields.

### R2: Requirements Subsections
The `create_spec()` function MUST generate `### R1:` style subsections in the Requirements section.

### R3: Release Field
The `create_spec()` function SHOULD use a placeholder that reminds the user to fill in the version (e.g., `{VERSION}` or read from pactkit.yaml), but MUST NOT use literal `TBD`.

### R4: Backward Compatibility
The generated template MUST pass `pactkit spec-lint` with zero ERRORs.

## Acceptance Criteria

### AC1: Generated Spec passes lint
- **Given** a fresh project with pactkit initialized
- **When** I run `python3 scaffold.py create_spec STORY-999 "Test Title"`
- **Then** running `pactkit spec-lint docs/specs/STORY-999.md` returns exit code 0

### AC2: Metadata table is correct
- **Given** a generated Spec file
- **When** I inspect the file content
- **Then** it contains `| Field | Value |` header and rows for ID, Status, Priority, Release

### AC3: Requirements have subsections
- **Given** a generated Spec file
- **When** I inspect the Requirements section
- **Then** it contains at least one `### R1:` subsection with RFC 2119 keyword
