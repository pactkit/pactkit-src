# BUG-010: _rewrite_yaml drops agent_models and rule_scopes sections

| Field     | Value |
|-----------|-------|
| Status    | Open |
| Author    | System Architect |
| Release   | 1.3.0 |

## Context

A 360-degree code audit revealed that `config.py:_rewrite_yaml()` does not serialize `agent_models` or `rule_scopes` sections. These fields are:

1. **Validated** by `validate_config()` (lines 326-377)
2. **Consumed** by `deployer.py` — `rule_scopes` at line 106, `agent_models` at line 109
3. **Missing from `_rewrite_yaml()`** — the function serializes ci, issue_tracker, hooks, lint_blocking, auto_fix, exclude, but NOT agent_models or rule_scopes
4. **Missing from `_BACKFILL_KEYS`** (line 198) — they are never auto-backfilled on upgrade

When `auto_merge_config_file()` runs (on every `pactkit init` / `pactkit update`), it calls `_rewrite_yaml()` which rewrites the entire file, **silently deleting** any user-configured `agent_models` or `rule_scopes` sections.

### Secondary issues found in the same audit:

- `deployer.py:620`: `_deploy_hooks()` hardcodes `LANG_PROFILES.get('python', {})` for the lint command in hook templates, ignoring the project's actual `stack` config.
- `deployer.py:116`: When using `pactkit init -t /custom/path`, CI pipelines are generated at `claude_root.parent` which may not be the actual project root.

## Target Call Chain

```
pactkit init/update
  → deploy() → _deploy_classic()
    → auto_merge_config_file(yaml_path)  ← triggers _rewrite_yaml
      → _rewrite_yaml(path, data)        ← BUG: drops agent_models, rule_scopes
    → load_config(yaml_path)             ← now missing those sections
    → _deploy_rules(..., rule_scopes={}) ← empty because data was lost
    → _deploy_agents(..., agent_models={}) ← empty because data was lost
```

## Requirements

1. `_rewrite_yaml` MUST serialize `agent_models` section when present in data dict
2. `_rewrite_yaml` MUST serialize `rule_scopes` section when present in data dict
3. `_BACKFILL_KEYS` SHOULD NOT include `agent_models` or `rule_scopes` (they are optional advanced features, not default sections)
4. `_deploy_hooks` MUST use the project's configured `stack` to resolve the lint command, not hardcode `'python'`
5. Existing user values MUST NOT be lost on any `pactkit init` or `pactkit update` cycle

## Acceptance Criteria

### AC1: agent_models preserved through rewrite cycle
- **Given** a pactkit.yaml with `agent_models: {system-architect: opus}`
- **When** `auto_merge_config_file()` runs
- **Then** the rewritten file still contains the `agent_models` section with the user's value

### AC2: rule_scopes preserved through rewrite cycle
- **Given** a pactkit.yaml with `rule_scopes: {01-core-protocol: "src/**/*.py"}`
- **When** `auto_merge_config_file()` runs
- **Then** the rewritten file still contains the `rule_scopes` section with the user's value

### AC3: Hooks use correct stack lint command
- **Given** a project with `stack: node` in pactkit.yaml
- **When** `_deploy_hooks()` generates the pre_commit_lint hook
- **Then** the hook uses the node lint command (e.g., `npx eslint .`), not the python command

### AC4: Round-trip fidelity
- **Given** a fully-populated pactkit.yaml with all sections (including agent_models, rule_scopes, exclude)
- **When** `auto_merge_config_file()` runs and triggers `_rewrite_yaml()`
- **Then** all sections are preserved in the output file
