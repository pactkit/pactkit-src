# BUG-016: GitHub Releases missing for v1.2.0 and v1.3.0

- **Release**: 1.3.0
- **Priority**: Medium
- **Type**: Release Process Fix

## Problem

Git tags exist for all releases, but GitHub Releases are only created up to v1.1.4:

| Version | Git Tag | PyPI | Plugin Sync | GitHub Release |
|---------|---------|------|-------------|----------------|
| v1.1.4 | Yes | Yes | Yes | Yes (Latest) |
| v1.2.0 | Yes | Yes | Yes | **Missing** |
| v1.3.0 | Yes | Yes | Yes | **Missing** |

The `pactkit-release` skill and release workflow create Git tags and push to PyPI, but never create GitHub Releases via `gh release create`. This means:
- The GitHub Releases page is stale (shows v1.1.4 as Latest)
- No downloadable source archives are attached to v1.2.0/v1.3.0
- Users browsing the GitHub repo see outdated release info

### Root Cause

The release process (`pactkit-release` skill) has no step for creating GitHub Releases. The v1.1.x releases were likely created manually, but this was not carried forward.

## Requirements

- MUST create GitHub Releases for v1.2.0 and v1.3.0 retroactively using `gh release create`
- MUST mark v1.3.0 as the Latest release
- MUST include a release body derived from the corresponding CHANGELOG section
- MUST add a `gh release create` step to the `pactkit-release` skill so future releases auto-create GitHub Releases
- SHOULD use `--notes-from-tag` or extract notes from CHANGELOG for the release body
- MUST NOT re-tag or modify existing Git tags

## Acceptance Criteria

### AC1: v1.2.0 GitHub Release created
- **Given** tag `v1.2.0` exists but has no GitHub Release
- **When** the fix is applied
- **Then** `gh release view v1.2.0` returns a valid release

### AC2: v1.3.0 GitHub Release created and marked Latest
- **Given** tag `v1.3.0` exists but has no GitHub Release
- **When** the fix is applied
- **Then** `gh release view v1.3.0` returns a valid release with the "Latest" badge

### AC3: Release body contains CHANGELOG content
- **Given** the created GitHub Releases
- **When** viewing the release body
- **Then** it contains the relevant entries from `CHANGELOG.md`

### AC4: pactkit-release skill updated
- **Given** the `pactkit-release` skill prompt
- **When** a future release is performed
- **Then** the skill includes a step to run `gh release create` with CHANGELOG-derived notes

### AC5: Release list is current
- **Given** `gh release list` is run
- **When** inspecting the output
- **Then** v1.3.0 appears as Latest, v1.2.0 and v1.1.4 are listed

## Target Call Chain

Files to modify:
- GitHub Releases — create v1.2.0 and v1.3.0 via `gh release create`
- `src/pactkit/prompts/workflows.py` — add `gh release create` step to pactkit-release skill prompt
- `CHANGELOG.md` — read-only (extract release notes)
