# BUG-035: OpenCode Format Should Follow Dual-Layer Architecture

| Field | Value |
|-------|-------|
| ID | BUG-035 |
| Status | Draft |
| Priority | P1 |
| Release | 1.6.9 |

---

## Background

STORY-069 实现了 `--format opencode` 部署模式，但未遵循 Claude Code 的双层架构设计。当前实现在目标目录同时生成全局和项目级文件，导致：

1. 项目目录下出现本应在全局的 agents/, commands/, skills/ 子目录
2. opencode.json（项目级配置）被错误地放在全局目录
3. 与 Claude Code 的工作流不一致

**正确的双层架构**：

| 层级 | Claude Code | OpenCode | 生成时机 |
|------|-------------|----------|----------|
| 全局 | `~/.claude/` | `~/.config/opencode/` | `pactkit init` |
| 项目 | `$CWD/.claude/` | `$CWD/` | `/project-init` |

## Requirements

### R1: 全局部署不生成 opencode.json (MUST)

`pactkit init --format opencode` MUST NOT 在全局目录生成 opencode.json。

opencode.json 是项目级配置文件，应由 `/project-init` 生成。

### R2: 全局部署只包含共享资源 (MUST)

`pactkit init --format opencode` 生成的 `~/.config/opencode/` 目录 MUST 只包含：

```
~/.config/opencode/
├── AGENTS.md           # 全局指令（inline rules）
├── agents/             # 共享 agents
├── commands/           # 共享 commands
└── skills/             # 共享 skills
```

### R3: /project-init 支持 OpenCode 环境检测 (MUST)

`/project-init` playbook MUST 检测 OpenCode 环境（通过检测 `~/.config/opencode/` 或 `which opencode`），并生成 OpenCode 原生项目文件。

### R4: 项目级 OpenCode 文件生成 (MUST)

当 `/project-init` 检测到 OpenCode 环境时，MUST 生成：

```
$PROJECT/
├── opencode.json       # 项目配置
└── AGENTS.md           # 项目指令（可 @import 全局 AGENTS.md 或 inline）
```

### R5: opencode.json 项目配置结构 (MUST)

项目级 opencode.json MUST 包含：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["AGENTS.md", "docs/product/context.md"]
}
```

注意：`provider`/`apiKey`/`model` 由用户自行配置，PactKit 不生成。

### R6: 与 Claude Code 双层架构对等 (SHOULD)

OpenCode 部署模式 SHOULD 与 Claude Code 保持相同的工作流：

1. `pactkit init --format opencode` → 全局部署
2. 用户进入 OpenCode 界面
3. `/project-init` → 项目级初始化

## Acceptance Criteria

### AC1: 全局部署无 opencode.json

- **Given** 用户运行 `pactkit init --format opencode`
- **When** 部署完成
- **Then** `~/.config/opencode/` 目录存在 AGENTS.md, agents/, commands/, skills/
- **And** `~/.config/opencode/opencode.json` 不存在

### AC2: /project-init 生成项目级配置

- **Given** OpenCode 环境已安装（`~/.config/opencode/` 存在）
- **When** 用户在项目目录运行 `/project-init`
- **Then** 项目根目录生成 `opencode.json` 和 `AGENTS.md`

### AC3: 现有测试兼容

- **Given** STORY-069 的 19 个测试
- **When** 修改后运行测试
- **Then** 需要更新的测试：`test_opencode_json_at_root` 应验证项目级生成，而非全局

## Target Call Chain

```
# 全局部署
pactkit init --format opencode
→ deployer.py:_deploy_opencode()
   → _deploy_agents_md_inline()  # AGENTS.md (inline rules)
   → _deploy_agents()            # agents/
   → _deploy_commands()          # commands/
   → _deploy_skills()            # skills/
   # 不调用 _deploy_opencode_json()

# 项目级初始化
/project-init
→ 检测环境 (Claude Code vs OpenCode)
→ 如果 OpenCode:
   → 生成 $CWD/opencode.json
   → 生成 $CWD/AGENTS.md (项目指令)
   → 生成 $CWD/docs/product/sprint_board.md
   → 生成 $CWD/docs/product/context.md
```

| SEC-6 | No | No API endpoints |

## Out of Scope

- OpenCode 全局 opencode.json 配置（用户自行管理 provider/apiKey）
- OpenCode 与 Claude Code 的运行时兼容性
- 从 Claude Code 迁移到 OpenCode 的自动工具
