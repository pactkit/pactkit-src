## Background

2026-09-03 全天工作暴露两个系统性盲区：①规则有效性只能靠事后考古（487MB 对话记录挖掘是一次性法证作业，不可持续）；②部署所有权账本三种缺陷形态横跨数月无人察觉（每段单测都绿）。用户核心要求（原话）："得能消费，消费完告诉用户调整什么，是 pactkit 的参数问题还是 pactkit 的 bug，这些有了，才能更好的指导用户使用。"

设计原则（ADR-0001 延伸）：消费端必须是 code 层阈值（doctor WARN / garden 建议）或已有流程必经点，不新造"看报表"仪式——被动等人读的遥测遵循率与条件触发规则相同（~2%）。

## Technical Design

### Lateral Scan Results

- Operation "事件记录": 2 处同型（run_events.append_event + gates.jsonl 的 record_gate_event）→ 复用 gates.jsonl 的项目级 append-only 模式（rules.jsonl）
- Operation "doctor 检查": 15+ 处 check_* 模式 → 复用（check_rule_health 返回 dict + findings）
- Operation "garden 巡检检测": 3 处 check_* → 复用（check_dead_rules）
- Operation "CLI 子命令": 全天新增 3 例（lint-adr/accept-candidates/guide show）→ 复用注册模式

### Capability Assessment

| Need | Source | Decision |
|------|--------|----------|
| 事件存储 | .pactkit/events/gates.jsonl 模式 | Reuse（新增 rules.jsonl 同型） |
| guide 内容输出 | GUIDE_FILES 渲染 + DEPLOY_PROBE_PATHS 路径探测 | Reuse |
| 检查函数模式 | doctor.check_* / garden.check_* | Reuse |
| 阈值配置 | pactkit.yaml 分节模式 | Reuse（新 telemetry: 节） |

### 采集端设计（R1-R2）

事件文件 `.pactkit/events/rules.jsonl`（项目级 append-only，同 gates.jsonl；gitignored，全程本地）：

| 事件 | 记录点 | 载荷 |
|------|--------|------|
| `rule_warning` | spec_linter 输出 W 级警告时（当前仅 W012，扩展点） | `{"rule": "W012", "spec": "<story_id>", "ts": ...}` |
| `guide_loaded` | `pactkit guide show <name>` 执行时 | `{"guide": "<name>", "ts": ...}` |
| `diagnosis_emitted` | doctor 诊断输出时（消费侧自观测） | `{"class": "config|bug|usage|rule_design", "finding": ...}` |

`pactkit guide show <name>`（咽喉点，用户已裁决）：按 DEPLOY_PROBE_PATHS 顺序探测宿主部署路径（classic/opencode: `skills/_rules/guides/<name>.md`；codex: `skills/project-act/references/guides/<name>.md`），打印内容并记录 guide_loaded。找不到时列出可用 guide 名并 exit 1。Act Phase 1.5 步骤 3 从"read the corresponding guide file from {GUIDES_PATH}/"改为"run `pactkit guide show <concern-guide>`"（四 adapter 同步渲染）。

### 诊断分类引擎（R3）——判据边界矩阵

**分类定义**（与 shared-execution 失败四分类同构）：

| 类 | 含义 | 输出形态 |
|----|------|---------|
| ① config | PactKit 参数问题 | 精确到键值的 yaml 修改建议 |
| ② bug | PactKit 缺陷 | "报 issue 附本输出" + workaround |
| ③ usage | 使用习惯问题 | 流程建议（非工具故障） |
| ④ rule_design | 规则设计问题 | 裁撤/合并/升级 code 强制建议——回流 PactKit 自身迭代 |

**信号 1：guide 零加载**（窗口 telemetry.guide_window_days，默认 30；逐 guide 判定，决策树按序短路）：

```
1. guide 在本宿主部署了吗？
   否 → ② bug："guide <X> 已注册但未部署到 <host>——请报 issue；workaround: pactkit update"
2. 项目 pactkit.yaml 的 guides: 列表排除了它？（当前架构 guides 无条件部署,排除仅经显式 guides: 键;rules: 管 capsule 不管 guide——Act 时 E2E 证实按 rules: 判定会批量误报①类）
   是 → ① config："guides: 未含 <X>——加一行启用：<精确 yaml 片段>"
3. 项目历史 Spec 的关键词命中过该 guide 的 concern？
   （扫描 docs/specs/*.md 对照 engineering index 关键词表）
   否 → ④ rule_design："本项目无 <concern> 场景——guide 不适用，建议排除或与相邻 guide 合并（反馈 PactKit 维护者）"
   是 → ③ usage（中置信，标注）："concern 存在但 30 天零加载——Phase 1.5 被跳过或裸 Read 绕过；
        建议：Act Phase 1.5 出口核对 guide 清单；置信度中（咽喉点可被绕过）"
```

**信号 2：W012 触发率**（窗口内 rule_warning 事件 / spec-lint 运行次数）：

```
1. W012 触发的 Spec 实际含 '### Capability Assessment'？
   是 → ② bug："检测器误报——请报 issue 附 Spec 路径"（抽样核验最近 3 例）
2. 触发率 > telemetry.w012_rate_threshold（默认 0.5）？
   是 → ③ usage："plan 阶段评估表习惯缺口（<N>/<M> 缺）——建议团队约定 plan 出口自查"
3. 触发率 = 0 且含框架信号的 Spec 占比 > 0.3？
   是 → ④ rule_design（低置信）："W012 路由可能未生效或信号词覆盖不足——反馈 PactKit"
```

**信号 3：评估表出现率**（doctor 扫描 docs/specs/*.md，无需埋点）：

```
出现率 < telemetry.assessment_floor（默认 0.3）且 W012 触发率同步低
   → ② bug 或 ④ rule_design（两信号矛盾 = 检测链断裂，输出诊断建议人工核验一例）
出现率 < floor 且 W012 触发率高 → ③ usage（与信号 2 一致，合并输出）
```

**信号 4：config 排除项**（确定性，无决策树）：rules: 列表与 RULE_DEFINITIONS 差集 → ① config 提示（列出被排除项及各自动机，供用户确认是否有意）。

**边界规则**：每条 finding MUST 携带 `class` + `evidence`（触发判定的数据）+ `action`（具体动作文案）；三类及以上信号指向同一类时合并为一条；置信度低于高的 finding MUST 标注置信级别与"建议人工核验"提示。

### 消费端（R4-R5）

- **doctor**：新 `check_rule_health(project_root) -> dict`，读 rules.jsonl + config + specs，产出 findings 列表；接进 doctor 主输出（done Phase 2 自动触达）。阈值读 `telemetry:` 节，缺省用命名默认值。
- **garden**：新 `check_dead_rules(project_root) -> dict`——零加载 guide 巡检（复用信号 1 判定 2-4 步），输出裁撤/合并建议。
- **stats**：`pactkit stats --format json` 增加 rules 节（各事件计数原始视图）。

### 数据本地性（R6）

全部数据仅写入 `.pactkit/events/rules.jsonl`（gitignored）；MUST NOT 发网络请求、MUST NOT 含用户身份信息；载荷字段限于 rule/guide 名、story id、时间戳。企业隐私红线。

## Requirements

### R1: 事件采集 (MUST)

run_events 之外新增项目级 `.pactkit/events/rules.jsonl`（append-only，同 gates.jsonl 模式）；事件类型 rule_warning / guide_loaded / diagnosis_emitted；spec_linter 在输出 W012 时 MUST 追加 rule_warning 事件（含 story id）；事件写入失败 MUST NOT 阻断 lint 输出。

### R2: pactkit guide show 咽喉点 (MUST)

新 CLI 子命令 `pactkit guide show <name>`：按宿主探测序解析 guide 文件、打印内容、记录 guide_loaded 事件；未找到时列出可用 guide 名并 exit 1。Act Phase 1.5（commands.py）步骤 3 MUST 改用该命令（四 adapter 渲染同步）。playbook 预算增量 ≤ 等量裁剪。

### R3: 诊断分类引擎 (MUST)

新模块实现上述四信号决策树；每个 finding MUST 含 class/evidence/action 三元组；置信度非高的 finding MUST 标注；同类多信号 MUST 合并。分类引擎为纯函数（输入事件+config+specs，输出 findings），可单测。

### R4: doctor 消费端 (MUST)

`check_rule_health` 接入 doctor 主输出；阈值经 `pactkit.yaml` 的 `telemetry:` 节可配（guide_window_days=30 / w012_rate_threshold=0.5 / assessment_floor=0.3，命名默认值进 config schema）；doctor 输出格式与既有 WARN 一致（done Phase 2 自动触达）。

### R5: garden 死规则巡检 (MUST)

`check_dead_rules` 接入 garden 巡检；输出裁撤/合并建议（④ 类文案）；对配置排除的 guide 不报（① 类由 doctor 负责，避免双报）。

### R6: 数据本地性 (MUST)

全部遥测仅落 `.pactkit/`；无网络发送；载荷字段白名单（rule/guide/story/ts）；MUST 有测试锁定（构造事件断言无外呼字段）。

### R7: stats 原始视图 (SHOULD)

（AC 见 TC 对应——非阻塞 SHOULD：stats rules 节为原始视图，验证并入 AC4 的 doctor 输出核验；跳过时须 DEFERRED 注释）

`pactkit stats --format json` 增加 rules 节（事件计数、按 guide/rule 分组）。

## Acceptance Criteria

### AC1: guide show 全链路 (R2)

- **Given** 本机已部署 guides
- **When** `pactkit guide show caching`
- **Then** 输出 caching guide 内容；rules.jsonl 增一条 guide_loaded；`pactkit guide show nope` exit 1 且列出可用名

### AC2: W012 事件 (R1)

- **Given** 一个缺 Capability Assessment 的 Spec
- **When** `pactkit spec-lint`
- **Then** W012 照常输出且 rules.jsonl 增一条 rule_warning（含 story id）；事件写失败不影响 lint 退出码

### AC3: 四类归因边界 (R3)

- **Given** 四个构造场景（配置排除 / 文件缺失 / concern 存在零加载 / 无 concern 场景）
- **When** 诊断引擎运行
- **Then** 分别输出 ①②③④ 类，各含精确动作文案；③ 类含置信度标注

### AC4: doctor 集成 (R4)

- **Given** 一个 guide 30 天零加载且 config 排除
- **When** `pactkit doctor`
- **Then** 输出 ① 类 finding（含 yaml 修改建议）；阈值经 telemetry: 节可改

### AC5: garden 集成 (R5)

- **Given** guide 未被排除、无 concern 场景命中
- **When** `pactkit garden`
- **Then** 输出 ④ 类裁撤建议

### AC7: stats 原始视图 (R7)

- **Given** 含 rules.jsonl 事件的项目
- **When** `pactkit stats --format json`
- **Then** 输出含 rules 节（按 guide/rule 分组计数）

### AC6: 本地性锁定 (R6)

- **Given** 全部新增代码路径
- **When** 事件构造与写入测试运行
- **Then** 载荷仅含白名单字段；无网络调用（测试断言）
