# BUG-028: Ghost DEV_REF Residual in Check and Review

| Field       | Value                         |
|-------------|-------------------------------|
| ID          | BUG-028                       |
| Title       | Ghost DEV_REF residual in Check playbook and Review skill |
| Status      | Planned                       |
| Priority    | Medium                        |
| Release     | 1.6.4                         |
| Origin      | STORY-063 audit (incomplete fix) |

## Problem Statement

STORY-063 removed ghost `DEV_REF_BACKEND`/`DEV_REF_FRONTEND`/`TEST_REF_*` references from the Act playbook, replacing them with generic "Stack Reference". However, two locations were missed:

1. **`commands.py:245`** — Check Phase 1 Step 3 still says `consult DEV_REF_FRONTEND`
2. **`workflows.py:373-374`** — Review skill (REVIEW_PROMPT) still says `apply DEV_REF_FRONTEND` / `apply DEV_REF_BACKEND`

These string constants are defined in `references.py` and exported via `__init__.py`, but `deployer.py` never interpolates their content into any deployed file. The AI sees the name but cannot access the content — making these instructions unactionable.

Note: `references.py` defines 6 large constants (~8KB total) that are exported but never injected by `deployer.py`. However, these constants are protected by STORY-026 Spec and 33 tests in `test_stack_references.py` — they MUST NOT be removed without a separate Story that supersedes STORY-026.

## Root Cause

- `deployer.py` has no code path to inject `DEV_REF_*` / `TEST_REF_*` content into deployed files
- STORY-063 fixed Act but missed Check and Review
- No test covers the absence of ghost refs in Check/Review playbooks
- The constants themselves are NOT dead code (STORY-026 Spec requires them) — the bug is that playbooks reference them by name as if the AI can access their content, but `deployer.py` never injects the content

## Target Call Chain

```
references.py (defines DEV_REF_*, TEST_REF_*)
  → __init__.py (re-exports)
  → deployer.py (NEVER imports or uses them) ← gap
  → commands.py:245 (Check, ghost name in string literal)
  → workflows.py:373-374 (Review, ghost names in string literal)
```

## Requirements

### R1: Remove ghost DEV_REF from Check playbook
Check Phase 1 Step 3 (`commands.py:245`) MUST replace `consult DEV_REF_FRONTEND` with actionable stack-aware prose (same pattern as Act's "Stack Reference").

### R2: Remove ghost DEV_REF from Review skill
`workflows.py:373-374` (REVIEW_PROMPT) MUST replace `apply DEV_REF_FRONTEND` / `apply DEV_REF_BACKEND` with actionable stack-aware prose.

### ~~R3: Clean up dead code in references.py~~ — CANCELLED
> **Risk Assessment**: `test_stack_references.py` has 33 tests asserting these 6 constants exist with specific content (STORY-026 Spec). Removing them would cause 33 test failures. The constants are NOT dead code — they are Spec-mandated but not yet deployed. A future Story could inject them via `deployer.py`, but that is out of scope for this bugfix.

### R3: Add regression guard tests
Tests MUST assert that no `COMMANDS_CONTENT` value or workflow prompt string contains unresolvable `DEV_REF_*` or `TEST_REF_*` name references (i.e., names that appear in prose but whose content is never injected into the deployed file).

## Acceptance Criteria

### AC1: Check playbook has no ghost refs
Given the deployed `project-check.md`, when searched for `DEV_REF_` or `TEST_REF_`, then zero matches are found.

### AC2: Review skill has no ghost refs
Given `REVIEW_PROMPT` in `workflows.py`, when searched for `DEV_REF_` or `TEST_REF_`, then zero matches are found.

### AC3: Regression guard
Given the test suite, a test exists that asserts no `COMMANDS_CONTENT` value or workflow prompt string literal contains `DEV_REF_` or `TEST_REF_` as a name reference (since `deployer.py` never injects their content).
