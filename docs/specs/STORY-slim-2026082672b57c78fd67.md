## Background

The project is in declared maintenance mode (bugfix + release only,
S26 portfolio decision) yet accumulated feature mass through 2.21-2.23.
The 2026-08-26 review measured the bloat concretely; this story pays
down subtractive debt only — NO behavior additions. Every removal below
was verified against the working tree; items pinned by legacy tests
are explicitly scoped with their test-migration requirement.

1. **Completion rules implemented three times**:
   _validate_receipt's per-step chain (workflow_engine.py:1945-2228),
   workflow_validators._COMMAND_COMPLETION_VALIDATORS
   (workflow_validators.py:298-428), and
   WorkflowFinalizer._validate_pdca_completion
   (workflow_engine.py:3061) — of which the project-check and
   project-done branches are dead (only project-act ever calls it).
2. **Two step taxonomies, no reconciliation**:
   workflow_registry ACT_STEPS/PLAN_STEPS/COMMAND_STEPS
   (workflow_registry.py:44-61) vs the engine's ACT_WORK_UNITS /
   PLAN_WORK_UNITS / OTHER_WORKFLOW_UNITS (workflow_engine.py:111-216).
3. **cli.py main() is a ~1650-line monolith**: init/update/upgrade
   subparser definitions copy-pasted three times with drift (upgrade
   lacks --allow-adapter-skew though it runs the same compat gate);
   ~20 redundant per-branch pathlib imports are symptom management.
4. **Dead code**: generators/adapter.py — entire module referenced only
   by its own test (superseded by FormatProfile system); deploy()'s
   five accepted-but-ignored parameters (agent, no_git, no_external,
   non_interactive, mode); audit.py _check_h4/_check_h6 manual params
   never passed; _compute_score's four optional count parameters never
   supplied; scorecard dict built twice with drift (json_only variant
   omits story_id).
5. **Doctor deploy-root enumeration × 4**: doctor.py builds the same
   deployment-root candidate list four independent ways (:132, :367,
   :520-528, :549-568) instead of deriving from FORMAT_PROFILES — the
   profiles.py docstring explicitly promises "No other files need
   modification".

Test-pinned dead code (do NOT remove without migrating the governing
tests — recorded here so the constraint is explicit):
_build_rule_id_to_key (test_story_slim010), _cleanup_legacy_commands
(test_story_slim063), _generate_project_claude_md_if_missing alias
(test_bug_021/019/020).

## Requirements

### R1: Completion rules have one source of truth — DROPPED (superseded)

Dropped 2026-08-26: the engine moved to the frozen legacy package
(STORY-slim-20260826cb37edfdd4da) ahead of this story per the documented
ordering constraint. Deduplicating completion rules inside FROZEN code
adds churn without a maintenance payoff; the duplication dies with the
package when the usage-gated deletion lands.


The per-workflow completion rules MUST be defined in exactly one module
(workflow_validators registry); _validate_receipt and the finalizer
MUST delegate to it. Dead branches in
WorkflowFinalizer._validate_pdca_completion MUST be removed or
activated. Behavior for every currently-passing completion contract
MUST be preserved (verified by the existing test suite without
modification).

### R2: Step taxonomy single source — DROPPED (superseded)

Dropped 2026-08-26, same rationale as R1: both taxonomy surfaces live in
or derive from the frozen legacy engine.


workflow_registry and the engine MUST derive their step/unit
enumerations from one shared definition; a test MUST assert the two
surfaces cannot drift apart silently.

### R3: cli.py decomposition (MUST) — partially delivered

Delivered (2026-08-26): shared `_add_deploy_args` builder for
init/update/upgrade eliminating the copy-paste drift, --allow-adapter-skew
unified on upgrade, the deploy handler extracted to module-level
`_run_deploy_command`, and a golden help-surface test pinning the entire
argparse output byte-for-byte. The line-count targets (main < 400,
cli.py < 1400 — final 1663) are DEFERRED: with R1/R2 dropped after the
legacy freeze, the remaining extraction is mechanical handler movement
whose risk/benefit supports a dedicated follow-up rather than this
story. The drift class the requirement targets is dead.

### R4: Dead code removal with test migration (MUST) — partially delivered

Delivered (2026-08-26): generators/adapter.py and its test removed
(grep-verified: only self-referenced); the audit json_only scorecard is
now derived from the single result dict (the hand-built copy's story_id
omission fixed with it). DEFERRED with in-code comments: deploy()'s
agent/no_git/no_external/non_interactive parameters — the review finding
was partially stale (allow_skew IS used; the other four are documented
enterprise API surface, forwarded by the CLI, and non_interactive is
pinned by tests). NOT removed: audit's manual=/_compute_score optional
parameters — both are referenced in function bodies (further stale
review findings); they stay as guarded legacy branches.

### R5: Doctor deploy roots derive from FORMAT_PROFILES (SHOULD) — delivered for project-level sites

_project_host_guarantees and check_rule_ownership now derive their
format-to-directory mappings from a single FORMAT_PROFILES-based helper
(_project_deploy_dirs): adding a format to profiles.py needs zero
doctor.py edits (drift-guard test included). DEPLOY_PROBE_PATHS's
home-global paths and check_config_drift's yaml-parent logic remain
hand-rolled — global layouts (e.g. ~/.config/opencode) are not
expressed in FORMAT_PROFILES today.

## Acceptance Criteria

### AC1: completion delegation (R1)

- **Given** the completion-contract test suite (current tests, unmodified)
- **When** the refactor lands
- **Then** all completion tests pass and grep shows completion-rule logic defined in exactly one module

### AC2: taxonomy drift test (R2)

- **Given** the shared step definition
- **When** a new workflow step is added to either surface in a test fixture
- **Then** the consistency test fails

### AC3: argparse surface unchanged (R3)

- **Given** the CLI before and after decomposition
- **When** `pactkit --help` and every subcommand's `--help` output is captured and diffed
- **Then** outputs are identical (except the newly unified --allow-adapter-skew on upgrade, which is the sanctioned drift fix)

### AC4: adapter.py gone, suite green (R4)

- **Given** the removal commit
- **When** the full test suite runs
- **Then** zero failures and no module imports generators.adapter

### AC5: doctor roots single-sourced (R5)

- **Given** the FORMAT_PROFILES-derived helper
- **When** a new format is added to profiles.py in a test fixture
- **Then** doctor's probe paths include it without editing doctor.py
