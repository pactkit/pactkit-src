## Summary

BUG-030 added the `pactkit spec-lint` CLI subcommand with 14 unit tests, but no E2E test was added to `tests/e2e/cli/test_cli_e2e.py`. All other CLI subcommands (`init`, `update`, `version`) have E2E subprocess tests. The `spec-lint` subcommand is the only gap.

## Requirements

### R1: Add E2E subprocess test
An E2E test MUST be added to `tests/e2e/cli/test_cli_e2e.py` that invokes `pactkit spec-lint` via subprocess.

### R2: Verify exit code and output
The E2E test MUST verify exit code and basic output for both success and failure cases.

### R3: Follow existing test patterns
The E2E test SHOULD follow the existing pattern used by other CLI E2E tests in the same file.

## Acceptance Criteria

### AC1: E2E test for spec-lint single file
- **Given** a valid spec file exists
- **When** running `pactkit spec-lint <path>` via subprocess
- **Then** exit code is 0 and stdout contains "PASS"

### AC2: E2E test for spec-lint --all
- **Given** the project has spec files in `docs/specs/`
- **When** running `pactkit spec-lint --all` via subprocess
- **Then** exit code is 0

### AC3: E2E test for spec-lint no args
- **Given** no arguments provided
- **When** running `pactkit spec-lint` via subprocess
- **Then** exit code is non-zero and output contains usage/help info
