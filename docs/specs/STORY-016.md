# Spec STORY-016: CLAUDE.md hygiene — language matching rule & project context cleanup
- **Release**: 1.1.3

## Context
Two issues with CLAUDE.md files:
1. **Global `~/.claude/CLAUDE.md`** (generated by deployer): Missing a language-matching rule. All PDCA output is in English regardless of user's input language. If user writes in Chinese, agent should respond in Chinese.
2. **Project `.claude/CLAUDE.md`** (checked into git): Contains stale data ("909+ tests") and overly descriptive content. Needs cleanup to be more instruction-focused and less documentation-like.

## Target Call Chain
```
deployer.py → _deploy_claude_md() → writes ~/.claude/CLAUDE.md
  → references rules/01-core-protocol.md (contains language rule)

rules.py → RULES_MODULES['core'] → 01-core-protocol content
  → [NEW] add language-matching instruction

.claude/CLAUDE.md → project-level context for Claude Code
  → [UPDATE] prune stale data, keep architectural instructions
```

## Requirements
1. **MUST** add a language-matching rule to `RULES_MODULES['core']` (01-core-protocol) in `rules.py`:
   - "Match the user's language: if the user writes in Chinese, respond in Chinese; if in English, respond in English."
   - This rule applies to all PDCA command output, not just conversation.
2. **MUST** update `CLAUDE_MD_PROJECT_TEMPLATE` (or the project-level `.claude/CLAUDE.md`) to:
   - Remove stale metrics ("909+ tests")
   - Keep architecture overview (useful for Claude to understand the project)
   - Keep dev commands (useful for Claude to run tests/lint)
   - Add `@./docs/product/context.md` reference if not present (cross-session state)
3. **SHOULD** create a `CLAUDE_MD_PROJECT_TEMPLATE` in `rules.py` if one doesn't exist, so the deployer or init command can generate a sensible project-level CLAUDE.md for new projects.
4. **MAY** move the project `.claude/CLAUDE.md` content into a template that `pactkit init` generates for the target project.

## Acceptance Criteria

### Scenario 1: Language matching in core protocol
Given the `RULES_MODULES['core']` content in `rules.py`
When inspected
Then it contains a language-matching instruction (e.g., "match user language")

### Scenario 2: Deployed rules contain language matching
Given a fresh `pactkit init` deployment
When `~/.claude/rules/01-core-protocol.md` is read
Then it contains the language-matching rule

### Scenario 3: Project CLAUDE.md has no stale data
Given the project `.claude/CLAUDE.md`
When read
Then it does not contain "909+ tests" or other hardcoded metrics
And it references `@./docs/product/context.md`

### Scenario 4: Project CLAUDE.md is instruction-focused
Given the project `.claude/CLAUDE.md`
When read
Then it contains architecture overview and dev commands
And is structured as instructions to Claude, not human-readable documentation
