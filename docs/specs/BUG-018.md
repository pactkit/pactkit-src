# BUG-018: Issue Tracker verification missing in Done command — no backfill for skipped Plan step

| Field     | Value |
|-----------|-------|
| Status    | Open |
| Author    | System Architect |
| Release   | 1.3.2 |

## Context

The current issue tracker integration relies on a two-phase flow:
1. **Plan Phase 3.4**: Create GitHub Issue and add link to Sprint Board entry
2. **Done Phase 3.6**: Parse Sprint Board for issue link and close the issue

**Problem**: If Plan Phase 3.4 is skipped (due to model behavior variance, context pressure, or interruption), the Sprint Board entry has no issue link. Done Phase 3.6 then silently skips closure because it finds no link to parse.

**Observed Behavior**: When using Opus 4.5, the "Conditional" framing causes the model to sometimes skip the issue creation step, resulting in stories without GitHub Issues even when `issue_tracker.provider: github` is configured.

**Root Cause**: No verification or backfill mechanism exists. The system assumes Plan always executes correctly.

## Target Call Chain

```
/project-done
  → Phase 3.5.5 (NEW): Issue Tracker Verification
    → read pactkit.yaml → issue_tracker.provider
    → if github:
        → gh issue list --search "STORY-XXX"
        → if NOT found:
            → gh issue create (backfill)
            → update Sprint Board entry with link
        → if found but open:
            → proceed to Phase 3.6 for closure
  → Phase 3.6: Issue Tracker Closure (unchanged)
```

## Requirements

### R1: Issue Existence Verification
- The Done command MUST verify issue existence when `issue_tracker.provider` is not `none`.
- Verification MUST use `gh issue list --search "{STORY_ID}"` to check if a matching issue exists.
- The search MUST match the Story ID pattern (e.g., "STORY-039", "BUG-018").

### R2: Automatic Backfill Creation
- IF no matching issue is found AND `provider: github`, the command MUST create a backfill issue.
- The backfill issue title MUST follow format: `{STORY_ID}: {Story Title}`.
- The backfill issue body MUST include: `Spec: docs/specs/{STORY_ID}.md` and `**Status**: Backfilled during Done phase`.
- After creation, the Sprint Board entry MUST be updated to include the issue link.

### R3: Sprint Board Link Update
- IF a backfill issue is created, the Sprint Board entry MUST be updated with the issue URL.
- The link format MUST match existing convention: `[#{number}](url)`.
- The update MUST preserve all other content in the Sprint Board entry.

### R4: Non-Blocking Failure
- IF `gh` CLI is unavailable, the command MUST print a warning and continue.
- IF issue creation fails (API error, auth issue), the command MUST print a warning and continue.
- Verification failures MUST NOT block the Done workflow completion.

### R5: Provider None Behavior
- IF `issue_tracker.provider: none` or section is missing, verification MUST be skipped silently.
- No warning or output for skipped verification when provider is none.

## Acceptance Criteria

### AC1: Backfill on Missing Issue
- **Given** `issue_tracker.provider: github` is configured
- **And** a Story "STORY-040" exists in Sprint Board without an issue link
- **And** no GitHub Issue with "STORY-040" in title exists
- **When** `/project-done` is executed for STORY-040
- **Then** a GitHub Issue is created with title "STORY-040: {title}"
- **And** the Sprint Board entry is updated with the issue link
- **And** the issue is subsequently closed in Phase 3.6

### AC2: Existing Issue Detection
- **Given** `issue_tracker.provider: github` is configured
- **And** a GitHub Issue "#25 STORY-040: Feature X" already exists (open)
- **And** the Sprint Board entry for STORY-040 has no issue link
- **When** `/project-done` is executed for STORY-040
- **Then** no new issue is created
- **And** the Sprint Board entry is updated with link to #25
- **And** issue #25 is closed in Phase 3.6

### AC3: Provider None Skip
- **Given** `issue_tracker.provider: none` is configured
- **When** `/project-done` is executed
- **Then** no issue verification is performed
- **And** no `gh` commands are executed
- **And** no warnings are printed

### AC4: CLI Unavailable Graceful Failure
- **Given** `issue_tracker.provider: github` is configured
- **And** `gh` CLI is not installed or not authenticated
- **When** `/project-done` is executed
- **Then** a warning is printed: "Issue tracker verification skipped: gh CLI unavailable"
- **And** the Done workflow continues to completion

### AC5: Prompt Template Contains Verification Step
- **Given** the `project-done.md` command template in `commands.py`
- **When** the template content is inspected
- **Then** it contains a "Phase 3.5.5" or equivalent verification step before Phase 3.6
- **And** the step includes `gh issue list --search` instruction
- **And** the step includes backfill creation logic
