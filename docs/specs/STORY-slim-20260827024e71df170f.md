## Background

来源：`docs/product/harness-comparison-2026-08-27.md`（PactKit vs deepseek-harness / Codex CLI 三方对比）的 P0 结论。项目处于 "collecting friction points" 阶段，但存在四个结构性缺口：

1. **Checkpoint 覆盖式写入，丢失历史** — `ContinuationEngine._checkpoint_locked`（`src/pactkit/continuation.py`）每次 `atomic_write` 覆盖单个 JSON，只知道 run 的当前状态，无法回答"evidence 被推翻过几次、blocker 挂了多久、重试了几次"。对比方（dsh append-only 事件流、Codex 不可变 rollout JSONL、Claude transcript）已全部收敛到事件溯源模式。
2. **Friction 数据没有出口** — 项目策略是"拿到 friction data 前不加新功能"，但不存在任何结构化 run 指标命令，friction 观察全部依赖人工 anecdote（如 v2.21 friction observation）。
3. **Gate 降级靠 stdout WARN，无机器可读状态** — commit-gate 自锁保护是 fail-open + WARN（`commit_gate.py` run_gate 异常路径），企业审计问"门什么时候是虚掩的"没有结构化答案。
4. **Codex 宿主拦截只有 git pre-commit 兜底** — `commit_gate.py:install_hook` 只 merge `.claude/settings.json`；而 Codex 已有 12 事件原生 hooks 引擎（PreToolUse 可 block + `updated_input` 改写），PactKit 未接入。

**历史决策约束（R4 必须正视）**：2.21 时代 PactKit 曾拥有完整的 Codex App Server 执行桥（`pactkit-codex-work-unit`、resumable threads、leases），2.21/2.22 withdrawn 后被主动移除，Codex 适配器退到 `portable` 保证级（`doctor.py:check_codex_execution_capability` 含防御性代码防止旧 manifest 复活 runner 能力）。本 Spec 的 R4 是**有条件的机制重入**：只做薄注册（注册 hook 入口、不拥有执行生命周期），与被移除的 runner 架构有本质区别。两条硬政策继续有效：(a) Codex 已存在的 `config.toml` 字节不碰（两次清空事故后的 create-if-absent 政策，CHANGELOG 明文）；(b) hook 生效需用户 content-hash 信任确认，部署绝不静默生效。

**前置关联**：2.23.0 `pactkit-codex` 因 ownership 契约缺口延后（`pactkit_owned_files` 收窄导致 command-local references 的所有权证明拿不到，见项目记忆 project_230_release_followups）。R4 部署 hooks.json 会向 manifest 增加新的 owned 文件，**该缺口的修复（或其设计决策）应先于或同期于 R4 落地**。

## Requirements

### R1: Run 事件流（append-only event log） (MUST)

`ContinuationEngine` 的每次状态变更必须在既有 per-run 锁内追加一条类型化事件到 `<checkpoint 同目录>/events/<story_id>.jsonl`，checkpoint JSON 语义不变（继续作为投影物化视图，现有读取路径零改动）。

- 事件类型最小集：`step_entered` / `checkpoint_written` / `evidence_invalidated` / `blocker_raised` / `blocker_cleared` / `run_completed` / `run_archived`
- 每条事件：`{ts, story_id, event, step_id, status, detail}`，`detail` 复用 `_sanitize_evidence` 的清洗路径（secret redaction 不重复实现）
- 事件追加必须发生在 `_story_lock` 临界区内（与 checkpoint 写入同锁，防交错）
- fresh-cycle 归档（`_archive_completed`）时事件文件随 checkpoint 一起归档
- 单行一次 write，不产生半行；进程崩溃最多丢最后一条事件，不得损坏已有行

### R2: Friction 统计命令 (MUST)

新增 `pactkit stats` 子命令，从事件流聚合 run 指标并输出：

- 每 run 时长（首事件到终态事件）、blocker 停留时长按 `blocker_kind` 分桶、evidence 失效/返工次数、步骤级分布（哪一步最常被打回）
- `--format json` 机器可读输出（后续 dashboard 的数据源）；默认人类可读表格
- 对无事件文件的旧 run / 事件缺失：优雅降级为 `events: unavailable`，命令不得失败（backward compat）
- CLI argparse 表面变更必须同步更新 golden help snapshot 测试（`tests/e2e/cli/`）

### R3: Gate 执行完整度上报（enforcement status） (MUST)

统一 enforcement 状态模型 `full / degraded / unavailable`，所有 gate 输出机器可读状态，`pactkit doctor` 聚合呈现：

- 新增共享模块（如 `src/pactkit/enforcement.py`）：状态枚举 + 各 gate 的 reporter
- 覆盖三个 gate：commit-gate（含自锁保护降级路径）、coverage-gate（探测失败降级路径）、continuation finish-gate
- commit-gate 自锁保护语义不变（exit 0 + WARN），但降级状态必须可通过 `pactkit doctor --json` 的 enforcement 段查询——从"悄悄降级"变为"可查询的降级"
- doctor 人读输出增加 enforcement 汇总行

### R4: Codex 原生 hooks 薄注册 (MUST)

把 commit-gate 的拦截接入 Codex 宿主的原生 hooks 引擎（PreToolUse 拦截 `git commit`）：

- 部署 `.codex/hooks.json`（项目级，`hooks.json` 是 Codex 独立发现的文件，**不触碰 config.toml**）；create-if-absent only：文件已存在且非 PactKit 所有时跳过并报告，绝不修改
- handler 复用 `pactkit commit-gate --hook` 入口，按 Codex hook 事件 schema（`hooks/schema/generated/`）适配输入/输出（事件名 Claude-Code 风格对齐，但 schema 细节以本机 Codex 版本为准）
- `doctor.py:check_codex_hook_capability` 从 deprecated stub 恢复为真实检测：探测本机 Codex 版本是否支持 hooks 引擎，报告 hook 文件部署状态与信任状态
- 部署输出必须显式提示"hook 需要在 Codex 内完成信任确认才生效"；`enterprise.no_git` 下与现有通道一致跳过
- manifest 记录 hooks.json 为 owned file（受 `.pactkit-deployed.json` 所有权证明保护——依赖 ownership 契约缺口的修复）

### R5: Codex FormatProfile 能力标志修正 (SHOULD)

`profiles.py` codex profile 的 `excluded_agent_fields` 移除 `"hooks"`、复核 `supports_model_routing`；若本机 Codex 版本探测（R4 doctor 检测）显示能力标志与实际不符，doctor 须给出提示而非静默。

### R6: 事件查看命令 (MAY)

`pactkit continuation events <story_id>` 列出某 run 的事件流（调试与人工审计用）。

## Acceptance Criteria

### AC1: 事件流写入与投影一致 (R1)

- **Given** 一个进行中的 Act run（story 已有 preflight checkpoint）
- **When** 调用 `ContinuationEngine.checkpoint()` 推进到 red 步骤
- **Then** `events/<story_id>.jsonl` 新增 `step_entered`/`checkpoint_written` 事件各一条；checkpoint JSON 内容与事件流最终状态一致；既有读取路径（`read`/`finish_guard`/CLI `continuation status`）行为不变

### AC2: 阻塞事件可回溯 (R1)

- **Given** 一个 run 以 `blocked` 状态写入（blocker_kind=user_input），随后解除并继续
- **When** 读取该 story 的事件流
- **Then** 存在成对的 `blocker_raised` / `blocker_cleared` 事件，时间戳可计算停留时长；事件 `detail` 中无 secret 明文（清洗路径覆盖）

### AC3: 崩溃安全 (R1)

- **Given** 事件文件已存在若干完整行
- **When** 模拟进程在事件追加中途被杀死（写入半行后中断）
- **Then** 重新读取时损坏行被跳过并计入 WARN 统计，既有完整行不受影响，checkpoint 读写不受影响

### AC4: stats 聚合与降级 (R2)

- **Given** 项目内有 3 个已完成 run 的事件流（含 1 个带 blocker 的）
- **When** 运行 `pactkit stats --format json`
- **Then** 输出包含每 run 时长、blocker 分桶停留时长、步骤返工计数；`pactkit stats`（人类模式）正常渲染
- **Given** 一个 2.23.0 时代创建的旧 run（无事件文件）
- **When** 运行 `pactkit stats`
- **Then** 该 run 计入 `events: unavailable`，命令 exit 0

### AC5: golden CLI snapshot 同步 (R2)

- **Given** `pactkit stats` 子命令已加入 argparse
- **When** 运行 CLI e2e 测试
- **Then** golden help snapshot 已更新且全绿（无其他 CLI 表面意外变更）

### AC6: gate 状态可查询 (R3)

- **Given** commit-gate 处于自锁保护触发状态（内部异常路径）
- **When** 运行 `pactkit doctor --json`
- **Then** enforcement 段含 `commit_gate: degraded` 及原因；正常状态下为 `full`；coverage-gate 与 finish-gate 同理有对应状态

### AC7: Codex hooks 薄注册与信任提示 (R4)

- **Given** 项目执行 `pactkit init --format codex`（或 update）
- **When** 部署完成
- **Then** 项目 `.codex/hooks.json` 存在且含 PreToolUse→`pactkit commit-gate --hook` 条目；部署输出含信任确认提示；既有 `config.toml` 字节不变（前后 sha256 一致）

### AC8: Codex hooks 不越权 (R4)

- **Given** `.codex/hooks.json` 已存在且含用户自己的 hook 条目
- **When** 重复执行部署
- **Then** 用户条目原样保留（PactKit 条目幂等刷新或追加），无任何用户内容被删除/改写；`enterprise.no_git` 场景下整体跳过

### AC9: doctor Codex 能力检测恢复 (R4, R5)

- **Given** 本机安装了支持 hooks 引擎的 Codex
- **When** 运行 `pactkit doctor`
- **Then** Codex 能力段报告 hooks 引擎可用性与 hook 部署/信任状态；不支持 hooks 的旧版 Codex 下报告 `unavailable` 而非误报

### AC10: 事件查看命令 (R6)

- **Given** 一个含 5 条事件的已完成 run
- **When** 运行 `pactkit continuation events <story_id>`
- **Then** 按时间序列出全部事件（含类型/步骤/时间戳）；无事件文件时输出空态提示并 exit 0

## Target Call Chain

- **R1/R2**: `cli.py` `continuation checkpoint` 子命令 → `ContinuationEngine.checkpoint()` → `_checkpoint_locked()` → [`atomic_write(path_for())` 不变；新增锁内事件追加] → 新增 `src/pactkit/run_stats.py`（或并入 continuation.py）读取 `events/*.jsonl` → `cli.py` 新增 `stats` 子命令
