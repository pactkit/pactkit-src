# BUG-034: Plan Command Missing Spec Metadata Table Template

| Field | Value |
|-------|-------|
| ID | BUG-034 |
| Status | Draft |
| Priority | P1 |
| Release | 1.6.9 |

---

## Background

When running `/project-plan`, the generated Spec often fails `spec-lint` with E002 errors:
```
[ERROR] E002: Missing or empty required metadata field: ID
[ERROR] E002: Missing or empty required metadata field: Status
[ERROR] E002: Missing or empty required metadata field: Priority
[ERROR] E002: Missing or empty required metadata field: Release
```

**Root Cause**: The Plan command playbook (`src/pactkit/prompts/commands.py`) does not include an explicit metadata table template. It only mentions "Fill in the `Release` metadata field" but doesn't show the exact format. This causes the LLM to generate inconsistent formats like:
- `| **ID** | STORY-XXX |` (bold field names)
- `| Story ID | STORY-XXX |` (wrong field names)
- Missing `| Field | Value |` header

The spec-lint requires exact format:
```markdown
| Field | Value |
|-------|-------|
| ID | STORY-XXX |
| Status | Draft |
| Priority | P2 |
| Release | 1.6.9 |
```

## Requirements

### R1: Add Metadata Table Template to Plan Command (MUST)

The Plan command playbook MUST include an explicit metadata table template showing the exact required format with all four required fields (ID, Status, Priority, Release).

### R2: Use scaffold.py create_spec as Canonical Format (SHOULD)

The template SHOULD match the format generated by `scaffold.py:create_spec()` to ensure consistency across all spec generation paths.

## Acceptance Criteria

### AC1: Plan Command Generates Valid Metadata Table

- **Given** a user runs `/project-plan "new feature description"`
- **When** the Plan command generates a Spec file
- **Then** the Spec contains a metadata table with:
  - `| Field | Value |` header
  - ID, Status, Priority, Release fields (exact case)
  - Non-empty values for all fields

### AC2: Generated Spec Passes spec-lint

- **Given** a Spec generated by `/project-plan`
- **When** running `pactkit spec-lint docs/specs/{ID}.md`
- **Then** no E002 errors are reported

## Target Call Chain

```
User → /project-plan
     → LLM reads commands.py PLAN_PROMPT
     → LLM generates docs/specs/{ID}.md
     → spec-lint validates metadata table
```

**File to modify**: `src/pactkit/prompts/commands.py` (PLAN_PROMPT section)
