## Background

A zero-code design-baseline commit (harness-backend root commit,
2026-09-01) was blocked three times by the commit gate with "FULL —
impact mapping empty — full unit suite (safe default)" and finally
forced the agent to write tests, move them to `tests/unit/`, and
bootstrap a venv before the commit went through. Three defects
conspired, each violating the gate's own documented intent:

1. **Repo meta files break doc-only classification.** `.gitignore` and
   `.claude/settings.json` carry no runtime code, yet they disqualify
   the whole change set from the doc-only skip
   (`regression.py` `_DOC_ONLY_PATTERNS`), contradicting the module's
   own "doc-only — safe to skip tests" contract.
2. **"Repo has no tests" is treated as "tests failed".** The full
   strategy hard-codes `tests/unit/`; a repo whose tests live at
   `tests/` (or that has none yet) yields exit 4/5, and `run_gate`
   counts any nonzero returncode as RED — converting "nothing to
   verify" into "write tests before any commit".
3. **Missing pytest module reads as RED, not unavailable.** With no
   project venv, `pytest_command` falls back to the pipx interpreter;
   `python -m pytest` exits 1 with "No module named pytest", which
   `run_gate` reports as failing tests. This violates R3 self-lock
   protection (a gate that cannot run must WARN and allow) and is
   inconsistent with the existing `FileNotFoundError` → WARN path for
   a missing pytest binary.

## Fix

1. `regression.py`: `_DOC_ONLY_PATTERNS` gains `.gitignore`,
   `.claude/**`, `.codex/**` — agent/repo metadata with no runtime
   code. Tamper guard is a separate channel and is unaffected.
2. `commit_gate.py run_pytest`: the full-suite target falls back from
   `tests/unit/` to `tests/` when only the latter exists, so a
   non-convention suite is still run instead of erroring. A repo with
   no tests at all keeps the RED verdict — the TDD contract ("code
   changes require tests") is untouched, but the verdict message now
   says "no tests collected" instead of implying failures.
3. `commit_gate.py run_pytest`: output containing "No module named
   pytest" raises `GateUnavailable` → WARN + allow, matching the
   missing-binary path (R3).

Out of scope (unchanged): trunk full-suite rule, protected-branch
block rule, tamper guard, secrets gate.

Verification: focused unit tests for all three behaviors + full suite.
