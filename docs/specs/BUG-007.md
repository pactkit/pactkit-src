# Spec BUG-007: Stale /project-trace references in deployed agent and skill files
- **Release**: 1.2.0

## Context
In STORY-011 (v1.1.2), `/project-trace` was demoted from a standalone command to an embedded skill (`pactkit-trace`). However, three deployed files still reference the non-existent `/project-trace` command:
1. `agents/code-explorer.md` — lines 269, 275 reference `## Protocol (/project-trace)` and `commands/project-trace.md`
2. `agents/system-architect.md` — line 26 references `run /project-trace first`
3. `skills/pactkit-visualize/SKILL.md` — line 74 references `/project-trace`

When users encounter these references, they attempt to run a command that doesn't exist, causing confusion.

## Requirements
- All references to `/project-trace` as a standalone command MUST be updated to reference the `pactkit-trace` embedded skill instead.
- The `code-explorer` agent prompt MUST NOT reference `commands/project-trace.md` (file doesn't exist).
- The `system-architect` agent prompt MUST reference the trace skill correctly (e.g., "use pactkit-trace skill" instead of "run /project-trace").
- The `SKILL_VISUALIZE_MD` usage scenario MUST reference the trace skill, not the command.

## Acceptance Criteria

### Scenario 1: No /project-trace references in deployed files
- **Given** a fresh PactKit deployment (any format)
- **When** all deployed `.md` files are searched for `/project-trace`
- **Then** zero matches are found

### Scenario 2: code-explorer references trace skill
- **Given** the deployed `agents/code-explorer.md`
- **When** the Protocol section is read
- **Then** it references `pactkit-trace` skill (not `/project-trace` command)

### Scenario 3: system-architect references trace skill
- **Given** the deployed `agents/system-architect.md`
- **When** the Protocol section is read
- **Then** it says "use pactkit-trace skill" (not "run /project-trace")

### Scenario 4: visualize SKILL.md references trace skill
- **Given** the deployed `skills/pactkit-visualize/SKILL.md`
- **When** Usage Scenarios are read
- **Then** it references `pactkit-trace` skill for call chain tracing

## Design
Update three source locations in `src/pactkit/prompts/`:
1. `agents.py` — `code-explorer` prompt: replace `/project-trace` with `pactkit-trace` skill reference, remove `commands/project-trace.md`
2. `agents.py` — `system-architect` prompt: replace `/project-trace` with `pactkit-trace` skill reference
3. `skills.py` — `SKILL_VISUALIZE_MD`: replace `/project-trace` with `pactkit-trace` skill reference

## Target Call Chain
`deploy()` → `_deploy_agents()` → `AGENTS_EXPERT["code-explorer"]["prompt"]`
`deploy()` → `_deploy_agents()` → `AGENTS_EXPERT["system-architect"]["prompt"]`
`deploy()` → `_deploy_skills()` → `SKILL_VISUALIZE_MD`
