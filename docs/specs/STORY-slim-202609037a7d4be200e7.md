## Requirements

### R1: API/接口域三 guide (MUST)

api-integration 增服务端视角实践：分页规范（cursor 优先于 offset 及理由）、幂等设计（幂等键生成与存储）、错误响应格式（稳定错误码+可读 message+trace 关联，不泄漏内部）、API 版本策略。event-driven 增投递语义判据表（at-most/at-least/exactly-once 的实现代价与适用）、消费者幂等、死信队列（什么进 DLQ、谁消费、何时重放）。backwards-compatibility 增兼容判据表（字段新增/删除/改名的各自兼容策略）、弃用流程（双写期→弃用警告→移除的时间窗）、序列化兼容红线（枚举值只增不改语义）。

### R2: 数据域三 guide (MUST)

database 增迁移安全（expansion-contraction 三步法：加列→双写→删旧列，每步可独立回滚）、索引纪律（查询先于索引、复合索引最左前缀、写多读少的索引代价）、事务边界（短事务、不在事务内做外部调用）。caching 增缓存决策表（读多写少才值得、TTL 与一致性容忍的关系）、失效策略判据（写穿透/旁路缓存/事件失效的适用场景）、缓存三大反模式（击穿/穿透/雪崩各附后果与缓解）。data-consistency 增一致性级别判据表（强/最终/因果各自的实现代价）、分布式补偿（saga 反向操作先想清楚再开工）、乐观锁 vs 分布式锁选择。

### R3: 并发/运行时域六 guide (MUST)

concurrency 增并发模型判据表（IO 密集→asyncio/线程池、CPU 密集→进程池、何时不用并发）、有界资源红线（队列必须有界、worker 数量可配）、共享状态三选一（消息传递/锁/不可变数据）。async-patterns 增阻塞调用识别清单（同步 IO/requests/CPU 重活在 event loop 中的处理）、取消传播（子任务必须响应 cancel）、超时分层（连接/读/总时长各自含义）。memory-management 增 Python 特有实践（生成器替代中间列表、__slots__ 场景、循环引用与弱引用）、有界集合红线（任何 LRU/dict 缓存必须有上限）、流式处理大文件模式。performance-antipatterns 增检测优先级表（先测量再优化、热点定位方法）、N+1 识别与批量化、过早优化判别（无 profile 数据的优化=猜测）。resilience 增断路器状态机（closed/open/half-open 转换条件与阈值来源）、舱壁隔离（按依赖分组资源池）、降级设计（降级路径必须同样被测试）。graceful-shutdown 增信号处理清单（SIGTERM 语义、退出码约定）、排空顺序（先停接收→排空队列→关连接→刷盘）、关闭超时（强制 kill 的兜底时长）。

### R4: 质量域三 guide (MUST)

testing-strategy 增测试金字塔判据（单元/集成/E2E 的数量与速度配比）、测试数据管理（工厂优于共享 fixture、每个测试自建自清）、flaky 处置政策（隔离→归档→修复时限，flaky 测试不算通过）、覆盖率的诚实使用（行覆盖是下限不是目标，断言质量优先）。code-review-first 增审查清单分层（正确性/安全/可维护性/测试各查什么）、审查响应规范（每条意见附理由或代码建议，拒绝需论证）、自我审查步骤（提交前 diff 自读）。component-reuse 增查找顺序实践（stdlib→项目内→成熟三方→自写的决策树与验证方法）、包装层判断（何时直用何时包一层）、复用检查点（新写前 grep 两遍）。

### R5: 交付/运维域五 guide (MUST)

configuration 增配置分层判据表（代码常量/环境变量/配置文件/运行时各自的归属）、密钥处理红线（env 注入而非写文件、日志 redaction 联动）、配置校验（启动时 fail-fast 于 schema 校验）。operational-readiness 增健康检查设计（liveness vs readiness 语义区分、检查自身必须轻量）、部署清单（回滚触发条件与步骤预先写好）、容量红线（启动时打印关键资源配置）。dependency-supply-chain 增依赖准入判据（必要性/维护活跃度/许可证/传递依赖数）、锁定纪律（lockfile 提交、版本范围策略）、最小化替代顺序（stdlib→既有依赖→新依赖）。write-safety 增决策矩阵细化（写入前检查清单：文件存在？我生成过？manifest 知道它吗？）、候选文件协议（.new 后缀+人工接受的流程）。ui-state-accessibility 增状态完整性清单（loading/empty/error/disabled/optimistic 五态逐个确认）、焦点管理（弹窗陷阱/焦点还原）、可访问性红线（禁用 pointer-events:none 隐藏交互、颜色对比度阈值）。

### R6: 体量、锚点与部署纪律 (MUST)

全部 20 个 guide 的渲染输出 MUST ≤50 行（存量预算测试不动，内容适配预算）；每个 guide 的 Practice MUST 含至少一个判据表或红线清单；测试 MUST 为 20 个 guide 各设内容锚点断言（每 guide ≥3 个关键锚点，防漂移）；部署后 MUST 抽查三个 adapter 副本。
