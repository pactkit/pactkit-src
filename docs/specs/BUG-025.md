## Background

STORY-051 从 Done 中抽取了 `/project-release` 命令，但实现时重复了 `pactkit-release` skill 的部分逻辑，且功能不一致：

| 功能 | pactkit-release (Skill) | project-release (Command) |
|------|------------------------|---------------------------|
| Version update | ✅ | ❌ |
| Spec backfill | ✅ | ❌ |
| Snapshot | ✅ | ✅ |
| Archive | ✅ | ✅ |
| Git tag | ✅ | ✅ |
| **GitHub Release** | ✅ | ❌ |
| Pre-flight check | ❌ | ✅ |

这违反了 DRY 原则，且用户调用 `/project-release` 时无法获得完整的发布流程。

## Target Call Chain

```
project-release.md (Command)
  └── Phase 1: 调用 pactkit-release (Skill) 执行完整协议
      └── pactkit-release/SKILL.md
          ├── board.py update_version
          ├── board.py snapshot
          ├── board.py archive
          └── gh release create
```

## Requirements

### R1: Command 委托给 Skill
`/project-release` command MUST delegate to `pactkit-release` skill after pre-flight checks:
- Phase 0 (Pre-flight) SHOULD remain in the command (version detection, config check)
- Phase 1+ MUST call pactkit-release skill instead of duplicating logic

### R2: Skill 增加 Pre-flight 支持
`pactkit-release` skill SHOULD accept optional version parameter:
- If version provided: use it directly
- If version not provided: detect from `pyproject.toml` diff (same logic as command Phase 0)

### R3: 功能对齐
After refactor, `/project-release` MUST provide all capabilities of pactkit-release:
- Version update
- Spec backfill (Release: TBD → actual version)
- Snapshot + Archive
- Git tag
- GitHub Release creation

## Acceptance Criteria

### AC1: Single Implementation
**Given** the refactored project-release command
**When** reading project-release.md
**Then** it MUST NOT contain snapshot/archive/tag logic inline; it MUST reference pactkit-release

### AC2: Full Release Flow
**Given** a user runs `/project-release` after a version bump
**When** the command completes
**Then** ALL of the following MUST be done:
- Snapshots created in `docs/architecture/snapshots/`
- Completed stories archived
- Git tag created
- GitHub Release created with CHANGELOG notes

### AC3: Backward Compatible
**Given** pactkit-release is called by Done Phase 3.8 (legacy path)
**When** invoked without explicit version
**Then** it MUST auto-detect version from pyproject.toml
