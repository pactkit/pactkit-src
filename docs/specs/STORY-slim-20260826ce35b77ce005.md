## Background

Full-codebase review (2026-08-26) found the verification/gate subsystem —
the core value of a governance tool — inverted or fail-open in eight
places. A governance gate that reports green when it verified nothing is
worse than no gate. All line references verified against the working tree
on 2026-08-26.

1. **pip-audit exit-code inversion** (audit.py:688): pip-audit exits 1 when
   vulnerabilities are found, but the JSON is parsed only inside
   `if result.returncode == 0:` — vulnerabilities are reported as zero.
   Secondary: line 691 labels "a fix exists" as critical.
2. **Substring identity matching** (done_verify.py:168): `rid in case_text`
   makes "R1" match "R10"; a case file referencing only R12 satisfies
   R1-R9. Same class at done_verify.py:134 where STORY-slim-10 matches an
   archive mentioning STORY-slim-100.
3. **Directory passed to load_config** (doctor.py:455, audit.py:1168):
   `load_config(Path('.'))` raises IsADirectoryError, swallowed by
   `except Exception: pass` — the stack-aware source_dirs check and the
   suggested-task developer prefix have never worked. Correct pattern
   exists 30 lines up (doctor.py:421).
4. **coverage_gate fail-open** (coverage_gate.py:62): bare "python" instead
   of the venv-aware pytest selection (commit_gate.py:93 has it —
   duplicated logic that diverged); files whose module path fails to
   resolve silently vanish from results; verdict "block" exits 0 at
   cli.py:1540 — violates the project's own "Code Enforces, Prompt
   Instructs" constitution.
5. **commit_gate input-collection failure masquerades as skip**
   (commit_gate.py:77-85): nonzero git return codes are ignored;
   changed == [] produces a confident "doc-only change" SKIP. Also
   tests/** is classified doc-only, so test-modifying commits never run
   tests.
6. **audit silent exception swallowing** (audit.py:440/455/469/594/792/826):
   _collect_findings/_collect_insights/_compute_hotspots use
   `except Exception: pass` — a crashed analyzer is indistinguishable
   from "no findings".
7. **no_secrets narrow and fail-open** (audit.py:257-266): initialized
   True; any probe error leaves it True; pathspec misses id_rsa, *.pem,
   *.p12, *.pfx, secrets.json.
8. **Single-layer audit corrupts the scorecard** (audit.py:1132-1143,
   1212): `--layer H1` hardcodes other layers to level 0 yet
   unconditionally overwrites harness_audit.json — ready flips to NO,
   story_id binding is lost.

Lateral scan: venv-aware pytest selection exists once (commit_gate.py:93);
word-boundary matching exists nowhere; the fix direction is to reuse and
share, not add new copies.

## Requirements

### R1: pip-audit verdict correctness (MUST)

The dependency-health check MUST parse the pip-audit JSON whenever the
exit code is 0 or 1 (0 = clean, 1 = vulnerabilities found), and MUST
report a probe error for exit codes >= 2 or subprocess failures. The
secondary count MUST be labeled fixable (vulnerabilities with available
fix versions) — pip-audit JSON carries no severity field, so a
severity-based count is technically infeasible (RFC amendment
2026-08-26); the vulns headline count is the severity-agnostic truth.

### R2: Identity matching by word boundary (MUST)

done_verify MUST match requirement IDs, acceptance-criteria IDs, and
story IDs with word-boundary semantics (e.g. `re.search(rf"\b{rid}\b",
text)`), eliminating substring false-positives (R1 vs R10,
STORY-slim-10 vs STORY-slim-100).

### R3: Correct config loading in doctor and audit (MUST)

check_stale_graphs (doctor.py) and the hotspot developer-prefix lookup
(audit.py) MUST resolve the effective config via
find_pactkit_yaml(project_root) followed by load_config(config_path),
matching the established pattern. A missing config MUST degrade to an
explicit warning, never a silent default.

### R4: coverage_gate fails closed (MUST)

coverage_gate MUST reuse a single shared venv-aware pytest command
helper (extracted from commit_gate.py; no second copy). Every input
source file MUST appear in the result (unresolvable module paths MUST be
reported as a distinct failure, not dropped). The CLI handler MUST exit
non-zero when the verdict is "block".

### R5: commit_gate collection failures are explicit (MUST)

A nonzero git return code, missing git binary, or timeout during changed-
file collection MUST produce an explicit "collection-failed" outcome with
exit code 1 — it MUST NOT be reported as "doc-only change". Changes under
tests/** MUST NOT be classified doc-only: they MUST trigger the mapped
test run for the modified test files.

### R6: audit failures are visible (MUST)

The persisted-audit path (H1-H7 layer checks) MUST surface an internal
exception as an explicit error entry plus a checks_failed field in the
result — a crashed analyzer MUST NOT be indistinguishable from "no
findings". The verbose-only collectors (_collect_findings,
_collect_insights) do not feed the persisted scorecard; their internal
per-probe failures MUST log a warning to stderr (scope clarification
2026-08-26: only the persisted path can corrupt the governance record).

### R7: no_secrets coverage (SHOULD)

The secret-file pathspec SHOULD include id_rsa, *.pem, *.p12, *.pfx, and
secrets.json, and a probe failure SHOULD downgrade the check to an
explicit "unknown" state rather than PASS.

### R8: single-layer audit MUST not overwrite the full scorecard (MUST)

When --layer is passed, the persisted harness_audit.json MUST be either
left untouched or updated only for the requested layer's entry;
hardcoding other layers to level 0 MUST NOT reach the persisted record.

## Acceptance Criteria

### AC1: vulnerabilities reported when pip-audit exits 1 (R1)

- **Given** a mocked pip-audit subprocess that exits 1 with a JSON body containing two vulnerabilities
- **When** the dependency-health check runs
- **Then** vulns == 2 and details carry both entries

### AC2: R10 does not satisfy R1 (R2)

- **Given** a spec with MUST items R1-R12 and a case file whose only reference is "R12"
- **When** done-verify runs
- **Then** R1 through R11 FAIL and only R12 PASSES

### AC3: stack-aware source dirs actually load (R3)

- **Given** a project with a pactkit.yaml configuring a non-Python stack
- **When** pactkit doctor runs
- **Then** the stale-graph check reads the configured source_dirs (verified via monkeypatched load_config receiving the yaml path, not a directory)

### AC4: coverage block verdict exits non-zero (R4)

- **Given** a coverage result whose overall verdict is "block"
- **When** the CLI coverage-gate handler runs
- **Then** the process exits with code 1

### AC5: dropped files surface as failure (R4)

- **Given** two changed source files where one's module path cannot be resolved
- **When** the coverage check runs
- **Then** the unresolved file is reported as a failure entry, not absent from results

### AC6: git failure is not doc-only (R5)

- **Given** a git subprocess that returns nonzero during changed-file collection
- **When** commit-gate runs
- **Then** the outcome is "collection-failed" with exit code 1, not a doc-only SKIP

### AC7: crashed analyzer is visible (R6)

- **Given** a layer analyzer that raises during _collect_findings
- **When** pactkit audit runs
- **Then** the result includes an explicit error indicator and does not report a clean audit

### AC8: single-layer probe preserves the scorecard (R8)

- **Given** a persisted harness_audit.json with a passing full scorecard
- **When** pactkit audit --layer H1 runs
- **Then** the persisted record still contains the other layers' real levels and ready state


### AC9: secret pathspec covers key material (R7)

- **Given** a repo containing an id_rsa file and a server.pem file
- **When** the no_secrets check runs
- **Then** both are flagged
