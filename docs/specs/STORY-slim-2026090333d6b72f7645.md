## Background

2026-09-03 以权威 SDLC 标准（ISO/IEC/IEEE 12207 技术过程链、SWEBOK v4 知识域、ISO/IEC 25010 质量模型、Google SRE 实践）为参照系对 PactKit 工程规则做差距分析，T1 级四项缺口：

1. **ADR 制度缺失**（SWEBOK Architecture KA / ISO 12207 Architecture 过程）：架构决策以无结构散文记录在 Key Decisions/lessons——无备选方案、无 tradeoff、无 supersession 链，决策被推翻时找不到它推翻了谁。
2. **Validation 缺失**（ISO 12207 明确区分 Verification 与 Validation 两个过程）：Check 全部是对 Spec 的 verification（做对了没有），无 validation（做的是不是对的东西——真实终端用户路径适配性）。实证：OLA-VIP 2026-08-20 纠正"你不应该使用 admin 用户来做啊"——admin 权限过大测不出业务用户问题，属 validation 失败；同日上线的 setup-actor 语义只修了验证侧。
3. **Postmortem 制度缺失**（Google SRE）：hotfix 修完即止，无跨 session 的 blameless 复盘产物（时间线/根因/复发预防 action items）。daily-retro 是个人日程复盘，不承载 incident 复盘。2026-09-02 gate -qq 事故级别的问题无复发预防机制。
4. **write-safety 规则被 2.24 重构删除**（ISO 25010 可维护性子特性）：merge-over-replace 决策矩阵 + SSOT/no-dual-write 在 2.24 场景化重构中随旧 architecture 规则整体删除，部署态 0 文件残留（2026-09-03 验证）。实证：BUG-010、BUG-slim-089、2026-08-13 codex config.toml 两次被清空——该规则正是事故直接防线。

## Requirements

### R1: ADR 制度 (MUST)

PactKit MUST 新增 ADR（Architecture Decision Record）文档类型：`docs/architecture/governance/adr/ADR-{NNNN}-{slug}.md`。schema 注册进 SCHEMA_REGISTRY（必需节：Context / Options Considered / Decision / Consequences；元数据：ID / Title / Status / Date / Supersedes / Superseded-by）。Status 生命周期为 proposed / accepted / superseded。scaffold.py MUST 新增 `create_adr` 子命令；`pactkit lint-adr` MUST 镜像 lint-testcase 校验结构。context_gen 的 Key Decisions 段 MUST 聚合最近 accepted 的 ADR（镜像 _parse_last_lessons）。ADR 记录的决策与 Spec 冲突时，较新者为准并在 ADR 中标注。

### R2: Check Validation 语义 (MUST)

check contract invariants MUST 增加 validation 维度："user-path validation is distinguished from Spec-conformance verification — key scenarios are exercised through the real end-user path, not a privileged one"。check playbook Phase 5 verdict MUST 增加 Validation 行：对 Spec 声明的真实用户角色/路径验证关键场景（无特权捷径），与既有 setup-actor mismatch 反模式（验证侧）形成两侧闭合。

### R3: Postmortem 制度 (MUST)

hotfix playbook MUST 新增 Phase 3.7（Postmortem Check，commit 之后）：当修复的缺陷满足以下任一条件——用户可见影响、同类缺陷复发（grep 同模式位点非空）、数据损失风险——MUST 产出 `docs/architecture/governance/postmortems/{ITEM_ID}.md`，含时间线、根因、影响面、复发预防 action items；action items MUST 转为 board story（含 add_task 或 add_story）。不满足触发条件的修复 MUST 记录 skip 理由（一行 log，不产文档）。

### R4: write-safety guide 恢复 (MUST)

GUIDE_DEFINITIONS MUST 注册 `write-safety.md` guide：Trigger 为写入既有文件/配置/托管内容；内容为 merge-over-replace 决策矩阵（生成者独占→全量替换安全；混合所有权→增量 merge；不确定→merge）+ litmus test（"这个文件里有不是我生成的内容吗"）+ no-dual-write（同一 truth 不得有两个权威位置，其余降级为读缓存/投影）。engineering index MUST 增加对应 keyword 路由行（配置/config/写入/覆盖/merge/覆盖文件/settings）。内容从 legacy architecture 模块浓缩，不逐字恢复 140 行。

### R5: Adapter parity 与契约预算 (SHOULD)

所有 playbook/contract/guide 改动经 _render_prompt 与 guide 部署链到达四个 adapter 且语义一致；check/hotfix contract 新增行数各 SHOULD ≤ 3 行。

### R6: Knowledge Provenance——反编造纪律 (MUST)

capability-design capsule MUST 增加 Knowledge Provenance 段：关于外部 API、版本行为、配置键、协议格式的断言 MUST 来自验证过的来源，优先级为项目自身代码 > Context7 MCP/官方文档 > 训练记忆（最后手段，输出中标注 unverified 并在使用前核实）；凭记忆编造的 API/签名按缺陷处理。act playbook Phase 3 MUST 增加一步：调用外部接口/协议/第三方库 API 前，先经 Context7/文档/项目既有用法验证签名与行为。check playbook Phase 2 MUST 增加 fabrication 信号行：lint 的 undefined-symbol 结果（F821 等）与 type-checker 错误显式归类为编造检测而非风格问题。此为 Act 时用户补充授权项（"AI 做实现和设计时自己编造、不去查业内最佳实践"——2026-09-03 实证 pactsearch fabricated SQL 列名被产品级预校验拦截；2.24 删除的旧 solution 规则原有 Query path 优先级条款即此内容的前身）。

## Acceptance Criteria

### AC1: ADR 全链路 (R1)

- **Given** 项目已初始化
- **When** 依次执行 `scaffold.py create_adr` 生成 ADR、`pactkit lint-adr` 校验、`pactkit context` 刷新
- **Then** ADR 文件含全部必需节与元数据，lint 通过，Key Decisions 段含该 ADR 摘要行

### AC2: ADR supersession (R1)

- **Given** ADR-0001 status=accepted，新建 ADR-0002 声明 Supersedes: ADR-0001
- **When** `pactkit lint-adr ADR-0002` 且 context 刷新
- **Then** ADR-0001 的 Superseded-by 指向 ADR-0002（lint 提示补记或 scaffold 自动回写），Key Decisions 只聚合非 superseded 的 ADR

### AC3: Validation 语义部署 (R2)

- **Given** 渲染后的 check contract 与 project-check playbook
- **When** 检查 invariants 与 Phase 5
- **Then** contract 含 validation 区分语义；playbook Phase 5 含 Validation 行（真实用户路径，无特权捷径）

### AC4: Postmortem 触发与产物 (R3)

- **Given** 渲染后的 project-hotfix playbook
- **When** 检查 Phase 3.7
- **Then** 含三条件触发（用户可见影响/复发/数据风险）、产物路径、action items 回流 board 的 MUST、skip 理由记录

### AC5: write-safety guide 可路由 (R4)

- **Given** GUIDE_DEFINITIONS 注册 write-safety.md 且 engineering index 更新后
- **When** TestEveryDeployedGuideIsRoutable 与 TestEveryDeployedGuideIsRoutable::test_index_keyword_table_covers_every_routed_concern 运行
- **Then** 通过（guide 非孤儿、Plan keyword 表覆盖）

### AC6: Adapter parity (R5)

- **Given** 四个 adapter 的部署产物
- **When** 对比 check/hotfix 命令渲染内容
- **Then** validation/postmortem 语义四端一致

### AC7: Knowledge Provenance 三时点部署 (R6)

- **Given** 渲染后的 capability-design capsule、project-act Phase 3、project-check Phase 2
- **When** 检查三者内容
- **Then** capsule 含来源优先级与 unverified 标注要求；act Phase 3 含先验证后写步骤；check Phase 2 含 fabrication 信号行
