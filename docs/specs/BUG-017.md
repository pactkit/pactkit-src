# BUG-017: /project-init playbook generates incomplete pactkit.yaml

| Field | Value |
|-------|-------|
| ID | BUG-017 |
| Title | /project-init playbook generates incomplete pactkit.yaml |
| Status | Draft |
| Priority | P1 |
| Release | 1.3.1 |

## Problem Statement

The `/project-init` playbook instructs Claude to manually create a minimal `pactkit.yaml` with only 3 fields (`stack`, `version`, `root`), while `pactkit init` CLI generates a complete 70-line configuration file including `agents`, `commands`, `skills`, `rules`, `ci`, `hooks`, etc.

This inconsistency causes:
1. Projects initialized via `/project-init` have incomplete configuration
2. Missing component lists prevent `pactkit init` from deploying correctly (it reads from `$CWD/.claude/pactkit.yaml`)
3. Users must manually run `pactkit update` to backfill missing sections

## Root Cause

In `src/pactkit/prompts/commands.py`, the `/project-init` playbook Phase 1 Step 1 says:

```markdown
1.  **Action**: Check/Create `./.claude/pactkit.yaml` in **Current Directory**.
    - *Content*: `stack: <detected>`, `version: 0.0.1`, `root: .`
    - **Do NOT add any fields not listed above** (e.g., no `language` field).
```

This instruction is outdated and does not match the complete config generated by `generate_default_yaml()` in `config.py`.

## Requirements

1. The `/project-init` playbook MUST instruct Claude to run `pactkit init` CLI instead of manually creating `pactkit.yaml`.
2. The playbook MUST detect if `pactkit` CLI is available before invoking it.
3. If `pactkit` CLI is unavailable, the playbook SHOULD warn the user and provide fallback instructions.
4. The playbook MUST still manually create `.claude/CLAUDE.md` (project-level) as the CLI does not generate this file.
5. The generated `.claude/CLAUDE.md` MUST follow the template defined in the playbook (project name, dev commands, context.md reference).

## Target Call Chain

```
/project-init (playbook)
  └── Phase 1: Environment & Config
        ├── Step 1: Run `pactkit init` CLI (NEW)
        │     └── deployer.deploy()
        │           └── _generate_config_if_missing()
        │                 └── generate_default_yaml()
        └── Step 3: Create .claude/CLAUDE.md (manual, unchanged)
```

## Acceptance Criteria

### Scenario 1: pactkit CLI available
```gherkin
Given a project directory without .claude/pactkit.yaml
And pactkit CLI is installed and available in PATH
When /project-init is executed
Then Claude runs `pactkit init` to generate config
And .claude/pactkit.yaml contains complete configuration (agents, commands, skills, rules, ci, hooks)
And .claude/CLAUDE.md is created with project-level template
```

### Scenario 2: pactkit CLI unavailable
```gherkin
Given a project directory without .claude/pactkit.yaml
And pactkit CLI is NOT available in PATH
When /project-init is executed
Then Claude warns: "pactkit CLI not found. Install with: pip install pactkit"
And Claude creates a minimal .claude/pactkit.yaml as fallback
And .claude/CLAUDE.md is created with project-level template
```

### Scenario 3: pactkit.yaml already exists
```gherkin
Given a project directory with existing .claude/pactkit.yaml
When /project-init is executed
Then Claude runs `pactkit update` to refresh config (backfill missing sections)
And existing user customizations are preserved
And .claude/CLAUDE.md is created if missing (not overwritten if exists)
```

## Implementation Notes

1. Modify `COMMANDS_CONTENT["project-init.md"]` in `src/pactkit/prompts/commands.py`
2. Update Phase 1 Step 1 to invoke `pactkit init` or `pactkit update`
3. Add CLI availability check: `command -v pactkit` or `pactkit version`
4. Keep Step 3 (manual CLAUDE.md creation) unchanged
