# Spec BUG-003: visualize.py ast.Import only captures last alias in multi-import
- **Release**: 1.1.2

## Context
In `_build_file_graph()`, when processing `ast.Import` nodes, the loop `for name in n.names: imported_module = name.name` overwrites `imported_module` on each iteration. For `import os, sys, json`, only `json` (the last) gets an edge in the dependency graph. The earlier imports are silently dropped.

## Requirements
- The system MUST create a dependency edge for every alias in a multi-name `import a, b, c` statement.
- The system MUST NOT produce duplicate edges for the same (consumer, provider) pair.
- The system SHOULD preserve existing behavior for single-name imports and `from X import Y` statements.

## Acceptance Criteria

### Scenario 1: Multi-name import produces all edges
- **Given** a Python file containing `import os, sys, json` where `os`, `sys`, `json` are all in the module index
- **When** `_build_file_graph()` processes the file
- **Then** edges are created for all three imported modules, not just the last one

### Scenario 2: Single-name import unchanged
- **Given** a Python file containing `import config`
- **When** `_build_file_graph()` processes the file
- **Then** exactly one edge is created (same as before)

## Design
Move the edge-resolution logic inside the `for name in n.names` loop so each alias is processed independently.

## Target Call Chain
`visualize()` → `_build_file_graph()` → `ast.walk()` loop → `ast.Import` branch
