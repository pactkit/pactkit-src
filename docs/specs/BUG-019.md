# BUG-019: STORY-039 venv implementation incomplete — detect_venv() never called, CLAUDE.md missing venv section

| Field     | Value |
|-----------|-------|
| Status    | Open |
| Author    | System Architect |
| Release   | 1.3.1 |

## Context

STORY-039 added virtual environment configuration support, but the implementation is incomplete:

1. `config.py:detect_venv()` function exists but is never called
2. `deployer.py` does not use venv config or pass it to templates
3. `rules.py:CLAUDE_MD_TEMPLATE` has no Virtual Environment section
4. `workflows.py:LANG_PROFILES` was not updated with venv-aware commands

**Observed Behavior**:
- Project has `.venv/` directory with `bin/python3`
- Config has `venv.auto_detect: true`
- Generated `.claude/CLAUDE.md` has NO venv section
- PDCA commands still use hardcoded `python3` instead of `.venv/bin/python3`

**Expected Behavior** (per STORY-039 AC3):
- `.claude/CLAUDE.md` should include Virtual Environment section when venv is detected
- Commands should reference venv-aware python paths

## Target Call Chain

```
deployer.py:_deploy_classic()
  → config.py:detect_venv(project_root)  # NEW: call detection
  → resolved_venv = venv_config.get('path') or detected_venv
  → deployer.py:_deploy_project_claude_md(venv_path=resolved_venv)  # MODIFY
    → rules.py:CLAUDE_MD_TEMPLATE  # MODIFY: add conditional venv section
```

## Requirements

### R1: Call detect_venv in Deployer
- The deployer MUST call `detect_venv()` when `venv.auto_detect` is true.
- The deployer MUST use explicit `venv.path` if set, overriding auto-detect.
- Resolution order: explicit path > auto-detected path > None.

### R2: Generate CLAUDE.md Venv Section
- IF a venv path is resolved (either explicit or auto-detected), the project CLAUDE.md MUST include:
  ```markdown
  ## Virtual Environment
  Always use the project's virtual environment:
  - **Activate**: `source {venv_path}/bin/activate`
  - **Python**: `{venv_path}/bin/python3`
  - **Pytest**: `{venv_path}/bin/pytest`
  - **Pip**: `{venv_path}/bin/pip`
  ```
- IF no venv is resolved, the section MUST be omitted.

### R3: Warning on Missing Explicit Path
- IF `venv.path` is explicitly set but the directory does not exist, print warning: "venv.path={path} not found, using system python"
- Auto-detect failures MUST be silent (per STORY-039 AC5).

### R4: Backward Compatibility
- Projects without `venv` config section MUST behave as before (system python).
- Projects with `venv.auto_detect: false` and no `venv.path` MUST use system python.

## Acceptance Criteria

### AC1: Auto-Detect Produces CLAUDE.md Section
- **Given** a project with `.venv/bin/python3` present
- **And** `pactkit.yaml` has `venv.auto_detect: true`
- **When** `pactkit init` is run
- **Then** `.claude/CLAUDE.md` contains "## Virtual Environment" section
- **And** the section references `.venv` paths

### AC2: Explicit Path Override
- **Given** `pactkit.yaml` has `venv.path: custom_venv`
- **And** `custom_venv/bin/python3` exists
- **When** `pactkit init` is run
- **Then** `.claude/CLAUDE.md` venv section references `custom_venv` paths

### AC3: No Venv When Not Found
- **Given** no venv directories exist
- **And** `venv.auto_detect: true`
- **When** `pactkit init` is run
- **Then** `.claude/CLAUDE.md` does NOT contain venv section
- **And** no warning is printed

### AC4: Warning on Missing Explicit Path
- **Given** `venv.path: nonexistent`
- **And** `nonexistent/` does not exist
- **When** `pactkit init` is run
- **Then** warning is printed about missing venv
- **And** `.claude/CLAUDE.md` does NOT contain venv section

### AC5: detect_venv Called in Deployer
- **Given** the deployer.py source code
- **When** inspected
- **Then** it imports and calls `detect_venv` from config.py
