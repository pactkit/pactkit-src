## Background

A 2026-08-30 fleet inspection (prompted by internal-adoption rollout
concerns) found the telemetry layer disconnected from real usage while
the hook layer works:

1. **Counters record nothing real.** `run_stats.authorization_decisions`
   (asked/granted/denied) is all zeros despite a genuine ask→grant flow
   on 2026-08-29 (pactsearch: auth block → user confirmation →
   `pactkit gate authorize repo` → token written). Run events stop at
   2026-08-25 because only the legacy workflow engine emits them, while
   actual daily work uses direct `/project-*` commands. For an
   enterprise rollout this means flying blind: friction (e.g. a measured
   2m37s commit-gate on a 412-test-file project) is invisible unless
   someone reads files by hand.
2. **Audit records persist credentials (real bug).** The same
   inspection found `secrets_gate.json` containing
   `"blocked: password-literal in 'PGPASSWORD=chatbi psql …'"` — the
   gate blocked the command but wrote the literal password into the
   on-disk audit record. A leak-prevention mechanism that manufactures
   persisted leaks violates L1 "never persist secrets" and is
   unacceptable for enterprise telemetry.

Aggregation already understands authorization events
(`run_stats.py` counts `authorization_asked/granted/denied`); the
problem is that nothing outside the workflow engine emits them.

## Requirements

### R1: Credential redaction in all persisted records (MUST)

A shared redaction helper MUST replace every credential pattern matched
by the secrets gate (plus the gate bypass env var assignments) with
`[REDACTED:{name}]` before ANY text derived from a command string is
persisted — enforcement `record_status` reasons, run-event `detail`
fields, and any future audit surface. Applied at minimum in
`secrets_gate` and `auth_gate` (whose block reasons embed command
prefixes). Existing already-persisted records with literal credentials
MUST be scrubbed once at upgrade time via `pactkit clean` (best-effort
scan of `.pactkit/enforcement/*.json` reason fields). The hook's
user-facing stderr message MAY still name the pattern kind but MUST NOT
repeat the literal credential.

### R2: Authorization events from the gates (MUST)

`auth_gate.check_command` MUST append an `authorization_asked` run
event on every block; `pactkit gate authorize` MUST append
`authorization_granted` on token creation. Events carry `story_id`
resolved best-effort from the active preflight receipt
(`.pactkit/preflight/{story}/current.json`, most recent mtime) and
`run_id: null`. `authorization_denied` semantics stay as-is (explicit
`continuation deny` only) — a block with no subsequent authorize is
derivable at stats time and is documented as such, not double-counted.

### R3: gate_blocked events (MUST)

Every gate that blocks (secrets, push, auth, spec, tamper, commit RED)
MUST append a `gate_blocked` run event with `detail = {gate, reason}`
(reason redacted per R1). This is the noise/friction measurement the
enterprise rollout needs: block frequency per gate, per project.

### R4: Skill-invocation telemetry (MUST)

The PreToolUse dispatch (`commit_gate.hook_entry`) MUST handle
`tool_name: "Skill"` by appending a `command_invoked` run event
(`detail = {command}` from `tool_input.command`, e.g.
`project-plan`/`project-act`) and exiting 0 — never blocking. The
matcher entry `"Skill"` MUST be registered by `install_hook`
(Claude-Code formats). EVENT_TYPES extends with
`command_invoked` and `gate_blocked`. Low-volume by construction:
events fire only on Skill calls and gate blocks, not on every Bash
command.

### R5: stats aggregation and rendering (MUST)

`run_stats` MUST surface the new telemetry: per-gate block counts and
per-command invocation counts appear in `pactkit stats` output
(human report + JSON), and `authorization_decisions` reflects the
gate-emitted events. A story-less aggregation bucket (story_id null)
MUST appear in reports rather than being dropped — gate telemetry is
project-scoped, not story-scoped. `pactkit doctor` unchanged.

## Acceptance Criteria

### AC1: Redaction before persistence (R1)

- **Given** a command containing `PGPASSWORD=chatbi psql …` reaching the secrets gate
- **When** the block record and gate_blocked event are written
- **Then** neither the enforcement JSON nor the event JSONL contains `chatbi`; both contain `[REDACTED:password-literal]`
- **And** the stderr message shown to the agent names the pattern kind without repeating the literal

### AC2: Authorization pair counts real traffic (R2, R5)

- **Given** a project with default enforcement config
- **When** `gh release create` is blocked and then `pactkit gate authorize release` runs
- **Then** the story event stream contains `authorization_asked` followed by `authorization_granted`, and `pactkit stats --format json` shows `asked >= 1, granted >= 1` for the project

### AC3: gate_blocked per-gate counting (R3)

- **Given** the secrets gate blocks twice and the auth gate once
- **When** `pactkit stats --format json` runs
- **Then** gate block counts show `secrets_gate: 2, auth_gate: 1`

### AC4: Skill telemetry (R4)

- **Given** a deployed project with the Skill matcher registered
- **When** the hook receives `{"tool_name": "Skill", "tool_input": {"command": "project-plan"}}`
- **Then** a `command_invoked` event with detail `{"command": "project-plan"}` is appended and the hook exits 0
- **And** `pactkit stats` reports the invocation count for `project-plan`

### AC5: One-time scrub of legacy records (R1)

- **Given** an enforcement JSON whose reason contains a literal credential
- **When** `pactkit clean` runs
- **Then** the reason is rewritten with `[REDACTED:…]` and the file remains valid JSON; records without matches are byte-identical

## Target Call Chain

```
secrets_gate/auth_gate check_command
  ├─ _redact_for_record(command)                (new shared helper)
  ├─ enforcement.record_status(redacted reason)
  └─ run_events.append_event: gate_blocked / authorization_asked
cli.py `gate authorize` → append_event: authorization_granted
commit_gate.hook_entry
  └─ tool_name "Skill" → append_event: command_invoked → exit 0
install_hook → matcher "Skill" registered
run_stats.collect_runs/_summarize → gate_blocks{}, command_invocations{}
cleaners.clean_artifacts → one-time enforcement reason scrub
```
