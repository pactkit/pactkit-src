## Background

PM-20260903-opencode-ledger-wipe 的类级 action item：当日三种账本缺陷形态（codex 不读账 / opencode 不记账 / opencode 记账被重建抹掉）每段单测都绿，坏的是三段之间的环。本 story 把"环"变成被测单元，防第四种形态。稳定性验证纪律（当日教训）：单轮通过 ≠ 稳定，断言必须连跑 3 轮。

## Technical Design

### 测试对象（函数级闭环，不实例化 deployer 类——适配器 deploy() 写真实宿主目录，不可入测试）

对四格式（classic/opencode/codex/copilot）各一段闭环：

```
round 1: preserve_or_write 写入内容 v1（无账本 → 直接写）
         → record_deployed_file（模拟适配器后处理后记账）/ write_command_manifest(references=...)
         → write_deploy_manifest 重建账本
         → 断言: 重建后 files 映射含该路径且 digest == 磁盘 v1
round 2: preserve_or_write 写入内容 v2（已变更）
         → 断言: 所有权被证明（in-place 覆盖,无 .pactkit-new）
round 3: 同 round 2（内容 v3）
         → 断言: 仍零候选（连跑 3 轮纪律）
```

- opencode 段模拟适配器后处理（v 写入后做一次字节变换再 record——复现"改写后记账"形态）
- codex 段验证合并视图：write_command_manifest 的 references 表 + 重建后的 deploy manifest,断言 read_command_references + previous_hashes 合并能证明 ownership
- copilot 段验证 prompts/ 布局的 files 映射覆盖

## Requirements

### R1: 四格式闭环测试 (MUST)

tests MUST 对 classic/opencode/codex/copilot 各实现上述三段闭环;每轮断言零候选与 digest 存续。

### R2: opencode 后处理形态覆盖 (MUST)

opencode 段 MUST 模拟"部署后字节变换再记账"形态（当日缺陷 2+3 的合成复现）。

### R3: codex 合并视图覆盖 (MUST)

codex 段 MUST 断言 read_command_references 表项在 write_deploy_manifest 重建后仍可作所有权证明（合并视图语义）。

## Acceptance Criteria

### AC1: 四格式闭环 (R1)

- **Given** 各格式布局的临时 root
- **When** 执行三段闭环（含内容两次变更）
- **Then** 每轮零 .pactkit-new;重建后 digest 存续

### AC2: opencode 后处理形态 (R2)

- **Given** 写入后变换字节再 record 的 opencode root
- **When** 下轮写入变更内容
- **Then** in-place 覆盖无候选（当日跑步机形态不可复现）

### AC3: codex 合并视图 (R3)

- **Given** references 表记账 + deploy manifest 重建后的 codex root
- **When** 以合并视图做所有权检查
- **Then** 证明成立,in-place 覆盖
