# Spec BUG-006: visualize _scan_files exclude list incomplete for marketplace deployment
- **Release**: 1.2.0

## Context
When PactKit is deployed in marketplace format, skill scripts, commands, rules, and agent files are placed alongside project source code (at project root). The `_scan_files()` function in `visualize.py` only excludes `{venv, _venv, .venv, .env, env, __pycache__, .git, .claude, tests, docs, node_modules, site-packages, dist, build}`. Directories like `skills/`, `commands/`, `rules/`, and `agents/` are NOT excluded, causing PactKit's own deployed files (e.g., `board.py`, `scaffold.py`, `visualize.py`) to appear in the project's architecture graph — polluting the dependency visualization.

## Requirements
- The `_scan_files()` exclude set MUST include `skills`, `commands`, `rules`, and `agents` directories.
- The exclude list SHOULD be documented as a constant (e.g., `SCAN_EXCLUDES`) for maintainability.
- Existing excludes MUST NOT be removed (backward compatibility).

## Acceptance Criteria

### Scenario 1: Marketplace deployment excludes PactKit directories
- **Given** a project deployed with `pactkit init` in marketplace format
- **When** `visualize` is run from the project root
- **Then** files under `skills/`, `commands/`, `rules/`, `agents/` are NOT included in the graph

### Scenario 2: Classic deployment unaffected
- **Given** a project using classic deployment (files in `~/.claude/`)
- **When** `visualize` is run from the project root
- **Then** behavior is identical to pre-fix (PactKit files are already outside project root)

### Scenario 3: Project source files still scanned
- **Given** a project with Python source files in `src/` or at project root
- **When** `visualize` is run
- **Then** project source files are included in the graph as before

## Design
Add `'skills', 'commands', 'rules', 'agents'` to the `excludes` set in `_scan_files()`. Extract the set to a module-level constant `SCAN_EXCLUDES` for clarity.

## Target Call Chain
`visualize()` → `_scan_files(root)` → `excludes` set check → `p.parts` filter
