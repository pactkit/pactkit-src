# BUG-013: Deployer reads config from wrong path — should use project-level config only

- **Type**: Bug
- **Priority**: High
- **Release**: 1.2.0
- **Discovered**: 360-degree audit — config path tracing

## Context

The deployer (`_deploy_classic`) reads config from `~/.claude/pactkit.yaml` (global), but the project-level config lives at `$CWD/.claude/pactkit.yaml`. This creates two divergent config files:

- **Global** (`~/.claude/pactkit.yaml`): has component lists but stale `version: 0.0.1`, `ci.provider: none`
- **Project** (`$CWD/.claude/pactkit.yaml`): has correct `version: 1.2.0`, `ci.provider: github` but missing component lists

The global config should not exist. There should be a single source of truth at `$CWD/.claude/pactkit.yaml`. The deployer should read from the project config, and `_generate_config_if_missing` should write a full config (with component lists) to the project path.

## Root Cause

`_deploy_classic()` (deployer.py:66-138) resolves `claude_root = Path.home() / ".claude"` and reads config from `claude_root / "pactkit.yaml"` — the global path. The project-level config is only backfilled by `_backfill_project_config()` but never used as the primary config source.

`load_config(path=None)` (config.py:107-137) defaults to `Path.home() / '.claude' / 'pactkit.yaml'` — the global path.

`_generate_config_if_missing()` (deployer.py:638-641) writes to `claude_root / "pactkit.yaml"` — again the global path.

## Target Call Chain

```
pactkit init/update → cli.py:deploy() → deployer.py:_deploy_classic()
  → config loaded from claude_root / "pactkit.yaml"  ← BUG: reads global
  → _generate_config_if_missing(claude_root)          ← BUG: writes global
  → _backfill_project_config(claude_root)             ← redundant after fix
```

Fix is in `_deploy_classic()`, `_generate_config_if_missing()`, `_backfill_project_config()`, and `load_config()`.

## Requirements

1. **MUST** change `_deploy_classic()` to read config from `$CWD/.claude/pactkit.yaml` (project-level), not `claude_root / "pactkit.yaml"`
2. **MUST** change `_generate_config_if_missing()` to write a full config (with component lists) to `$CWD/.claude/pactkit.yaml`
3. **MUST** remove `_backfill_project_config()` — no longer needed when there is a single config source
4. **MUST** change `load_config(path=None)` default path to `Path.cwd() / '.claude' / 'pactkit.yaml'`
5. **MUST NOT** break `pactkit init -t /tmp/preview` (target directory override still works)
6. **MUST NOT** delete the global `~/.claude/pactkit.yaml` — user can remove it manually
7. **SHOULD** print a warning if `~/.claude/pactkit.yaml` exists to inform user it is no longer used

## Acceptance Criteria

### AC1: Deployer reads project-level config
- **Given** a project with `$CWD/.claude/pactkit.yaml` containing `version: "1.2.0"`
- **When** `pactkit update` is run
- **Then** the deployer uses the project-level config (not the global one)

### AC2: New config generated at project path
- **Given** a fresh project with no `.claude/pactkit.yaml`
- **When** `pactkit init` is run
- **Then** a full config (with agents/commands/skills/rules lists) is generated at `$CWD/.claude/pactkit.yaml`
- **And** no config is generated at `~/.claude/pactkit.yaml`

### AC3: load_config default path changed
- **Given** `load_config()` called with no arguments
- **When** `$CWD/.claude/pactkit.yaml` exists
- **Then** it reads from `$CWD/.claude/pactkit.yaml`

### AC4: Target override still works
- **Given** `pactkit init -t /tmp/preview`
- **When** deployment runs
- **Then** config is read from `/tmp/preview/pactkit.yaml` (target-relative)
- **And** files are deployed to `/tmp/preview/`

### AC5: _backfill_project_config removed
- **Given** the deployer source code
- **When** inspected after the fix
- **Then** `_backfill_project_config` is no longer called or defined

### AC6: Orphan warning
- **Given** `~/.claude/pactkit.yaml` exists
- **When** `pactkit update` is run
- **Then** a warning is printed: "⚠️ Found orphaned ~/.claude/pactkit.yaml — config is now read from $CWD/.claude/pactkit.yaml"
