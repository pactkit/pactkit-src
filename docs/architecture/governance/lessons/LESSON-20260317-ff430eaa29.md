When two deploy functions share logic (classic/opencode), add missing functions one-by-one rather than creating a shared `_deploy_standard()` up-front — `_deploy_opencode()` was missing `auto_merge_config_file`, `_cleanup_legacy`, `_generate_project_agents_md`, and `_print_mcp_recommendations_opencode`; adding them separately is safer than a premature abstraction that could break the plugin/marketplace modes which use different parameter patterns (`_legacy_prefix`)
