# Test Case: STORY-slim-202608267c3989223b4d

Workflow engine robustness.

## TC-01: vanished artifact fails submit (R1, AC1)

- **Given** a receipt with an unavailable ("missing") evidence fingerprint
- **When** the submit acceptance path persists state
- **Then** an artifact_vanished WorkUnitError is raised before any state write

## TC-02: corrupt irrelevant sibling skipped (R2, AC2)

- **Given** one valid run and one unparseable unrelated run file
- **When** unit lookup runs
- **Then** the valid run is found and the corrupt file is skipped with a stderr warning

## TC-03: corrupt relevant target fails closed (R2, AC3)

- **Given** a run file that parses but fails validation and matches the query (unit or story)
- **When** the scan runs
- **Then** the WorkUnitError propagates

## TC-04: Windows lock path avoids fcntl (R3, AC4)

- **Given** os.name == "nt" with a fake msvcrt and fcntl import forbidden
- **When** the engine run lock is acquired and released
- **Then** only msvcrt locking calls occur

## TC-05: story binding serializes (R4, AC5)

- **Given** the bind lock held by one binder
- **When** a second bind_story runs concurrently
- **Then** it blocks until the first completes

## TC-06: transient git unavailability is not drift (R5, AC6)

- **Given** a checkpoint with real git digests and a probe returning "unavailable"
- **When** _stale_reasons evaluates
- **Then** no git/worktree drift reason is emitted; absent expected keys are not drift either

## TC-07: active v2 run blocks legacy resume explicitly (R5 follow-up)

- **Given** a legacy v1 checkpoint and an active v2 run bound to the same story
- **When** resume runs
- **Then** the decision is blocked with an explicit active-run reason (no git-probe quirk dependency)
